### 格式模块的单一层级来源

上述归属矛盾不能依赖同一语言模型再次判断来消除。新报告的格式 Skill 改为只提交
`outline_nodes`，每节点包含 `id/name/node_type/parent_id/requirements/citations`。
`parent_id` 是唯一归属来源；程序据此生成动态报告正文、层级、完整父路径和关系。
逻辑标是0级根，独立材料从1级开始；缺失父节点、循环、超过三级、名称或要求不在已读引文中都会拒绝并反馈。
编制要求采用原文片段，层级判断仍需要真实依据和支持性检查，结构校验不等于证明语义。
各节点只提交自身名称和要求的引文；程序按唯一父路径汇集已校验的祖先引文，使正文和关系都带完整证据。
不要求模型在每个子节点反复抄写祖先原文，也不自动拼接或替换模型给出的引文。

新协议保存在报告快照 `__outline_contract__` 中。缺少该键的历史报告继续按其已有 items 协议补跑，
不会隐式切换规则。前端和公开报告 API 仍接收原有 items/cells/relations，不需要新迁移。

### 格式材料清单的完整性核对

真实本地模型在节点结构合法时仍将两个子材料合并到父节点编制要求中；直接让模型对照已有节点
判断遗漏，也误报了空清单。因此完整性核对先独立读取原文，每6块生成带原文引用的
`outline_inventory`，不将已有节点或其编制要求放进清点提示。程序按材料名称及引用块对照，
父节点中的提及不算独立子节点，同名材料也不能用另一来源的节点覆盖。

已清点的块在本模块内缓存，补读新块时增补；修正结果始终与同一份清单对照，避免重复判断时
忘掉已发现的遗漏。补全采用精简任务，只生成缺失节点，程序保留已有节点并合并；重复旧ID、
无依据引文及非法层级依旧拒绝。补全最多两次，并计入32步上限，仍缺材料则模块失败，
不发布残缺的完整结果。引文错误包含节点ID和名称，便于精确修正。
格式纠正输入仅保留最近一份待修正大纲和完整阅读记录，避免重复错误稿挤占原文；完整执行记录仍保留。
新增节点、合并记录、最终节点和原文清单保存在执行记录中。清单本身仍由语言模型识别，这项检查降低遗漏风险，

## 实现边界

1. 知识库使用 `knowledge_collection`；独立知识库有 `kind=knowledge` 的文件存储项目，复用原有转换、解析、下载与版本服务，不出现在普通项目列表。来源身份由 `knowledge_source` 保留，不改写来源所属项目。
2. 引用携带集合、来源、项目文件、文档版本、解析批次和元素身份。服务端同时校验整条身份，删除资料或移除知识库后立即拒绝引用解析。
3. Skill 规则随应用打包到 `tender/resources/parse_skills`，不依赖被 Git 忽略的本地参考目录。领域规则来自用户提供的 12 个标准模块和通用兜底；历史分类 Skill 暂不调用。
4. 统一输出使用动态条目、列表项和表格行，拒绝没有引用或引用未读取原文的条目。模型支持性校验不等于人工确认；证据不支持的条目明确标为证据不足。
5. 格式模块适配为基于所有文件的格式正文提取组织层级与材料要求，并使用 PDF 锚点；不将 DOCX 元素序号冒充 PDF 坐标。
6. 现场 PostgreSQL 18.6 无 pgvector 扩展。首版以双精度数组存储向量，在已授权范围内进行精确余弦计算，和关键词结果融合。大规模库可后续接入 pgvector 加速；当前不提供近似最近邻索引。
7. 向量模型绑定唯一模型。模型 ID、远端模型名、服务地址组成嵌入空间标识；模型变化需重建索引，不跨空间混用。未配置、不可用或未重建的来源保留全文检索。
8. GraphRAG 使用有引用且通过支持性校验的领域关系，按项目和来源批次限定，最多两跳展开；关系列表展示依据。关系来自综合报告，未生成报告时不声称已使用图谱。
9. Worker 使用独立持久任务状态、定期派发、租约和数据库会话锁；问答和分析在 `extract` 队列执行。上线需要重启 API、worker 与 beat。
10. PDF 及可转换的 Office/文本资料进入解析，不再按清单/图纸角色排除。CAD 等未支持格式明确列为未覆盖，需要用户提供 PDF 或允许部分分析。
