### 格式模块的单一层级来源

上述归属矛盾不能依赖同一语言模型再次判断来消除。新报告的格式 Skill 改为只提交
`outline_nodes`，每节点包含 `id/name/node_type/parent_id/requirements/citations`。
`parent_id` 是唯一归属来源；程序据此生成动态报告正文、层级、完整父路径和关系。
逻辑标是0级根，独立材料从1级开始；缺失父节点、循环、超过三级、名称或要求不在已读引文中都会拒绝并反馈。
编制要求采用原文片段，层级判断仍需要真实依据和支持性检查，结构校验不等于证明语义。
各节点只提交自身名称和要求的引文；程序按唯一父路径汇集已校验的祖先引文，使正文和关系都带完整证据。
不要求模型在每个子节点反复抄写祖先原文，也不自动拼接或替换模型给出的引文。

节点协议由运行时提示词常量提供，报告快照只保存 Skill 正文。旧固定字段流程（全文扫描分派 +
固定 items 协议）已整体下线，`runtime_version=legacy` 的历史报告只读展示、不能补跑。

### 2026-10-09 字段值级证据绑定与独立问答 Agent

旧的 `kind/title/text/presentation/cells` 报告协议无法表达「某字段的某个解析值由哪些原文块支撑」，
本轮整体替换为字段—值—证据三层结构，未保留旧结构的兼容或回退分支：

- 提交内容 `items` 改为字段数组，每项为
  `{field(解析字段名), group(展示分类), sort_order(展示顺序), values(解析值数组), note}`；
  每个 value 为 `{value(解析值原文表述), citations([{block_id,quote}])}`。
  证据**逐值绑定**：同一字段出现多个值（原文与补充通知不一致等）时各自成项、各带自己的引用，
  不再把多个值合并进一段文字，前端因此能对每个值单独定位和判重。
- `relations`（subject/predicate/object/scope/condition/citations）保持不变；`research_summary` 保持不变。
  缺席性断言仍只写入 research_summary，不生成「条款缺失」条目。
- `validate_items` 只做结构、引文连续性与来源身份校验；`submit_analysis` 工具内 `validate_support`
  对字段逐项做支持性验证，未通过的字段返回可纠正反馈让子 Agent 修正，不进入已完成模块。
  关系断言在最终批同样包成字段单元一并验证，只有验证通过的关系进入图谱。
  支持性验证完全在 Agent 的提交工具内完成，worker 不再直接调用模型核对模块结果。
- 汇总只合并同 `field`、`group`、`note` 且 values 等价的字段断言，按值级对齐合并引用与模块来源；
  不同断言和冲突保留。报告创建时的 `runtime_settings` 快照不变，只作历史记录。

问答链路同样改为独立 Agent：新增 `agent/qa_agent.py` 的 `answer_with_agent`，
检索、补读、核对与作答都在一个 DeepAgents 图内完成，worker 只注入检索器、读取器和授权回调，
并把图内产出的字段/关系与既有关系图谱合并。问答不再以 `json_completion` 直接拼提示词调用模型。
QA 复用模块 Agent 的模型路由、证据账、摘要中间件和支持性验证，默认预算更小
（16 次模型请求、24 次工具调用、80 块证据）。

前端同步：`types/knowledge.ts` 以 `AnalysisField`/`FieldValue` 替换 `AnalysisItem`；
`ModuleMarkdown` 按 `group` 分组、按 `sort_order` 排序，同一字段多值或未通过校验时提示不一致，
每个值展示各自的引用定位；`ProjectAnalysis`、`QuestionPanel` 改为遍历 value 级引用；
旧的 `ReportItems.tsx` 与 `.report-item/.report-kind/.report-table` 样式删除。

## 实现边界

1. 知识库使用 `knowledge_collection`；独立知识库有 `kind=knowledge` 的文件存储项目，复用原有转换、解析、下载与版本服务，不出现在普通项目列表。来源身份由 `knowledge_source` 保留，不改写来源所属项目。
2. 引用携带集合、来源、项目文件、文档版本、解析批次和元素身份。服务端同时校验整条身份，删除资料或移除知识库后立即拒绝引用解析。
3. Skill 规则随应用打包到 `tender/resources/parse_skills`，不依赖被 Git 忽略的本地参考目录。领域规则来自用户提供的 12 个标准模块和通用兜底；历史分类 Skill 暂不调用。
4. 统一输出使用动态条目、列表项和表格行，拒绝没有引用或引用未读取原文的条目。模型支持性校验不等于人工确认；证据不支持的条目明确标为证据不足。
5. 格式模块适配为基于所有文件的格式正文提取组织层级与材料要求，并使用 PDF 锚点；不将 DOCX 元素序号冒充 PDF 坐标。
6. 现场 PostgreSQL 18.6 无 pgvector 扩展。首版以双精度数组存储向量，在已授权范围内进行精确余弦计算，和关键词结果融合。大规模库可后续接入 pgvector 加速；当前不提供近似最近邻索引。
7. 向量模型绑定唯一模型。模型 ID、远端模型名、服务地址组成嵌入空间标识；模型变化需重建索引，不跨空间混用。未配置、不可用或未重建的来源保留全文检索。
8. GraphRAG 使用有引用且通过支持性校验的领域关系，按项目和来源批次限定，最多两跳展开；关系列表展示依据。关系来自综合报告，未生成报告时不声称已使用图谱。
9. Worker 使用独立持久任务状态、定期派发、租约和数据库会话锁；问答和分析在 `extract` 队列执行。上线需要重启 API、worker 与 beat。
10. PDF 及可转换的 Office/文本资料进入解析，不再按清单/图纸角色排除。CAD 等未支持格式明确列为未覆盖，需要用户提供 PDF 或允许部分分析。

## 单标段编制的业务数据（数据版本 1，迁移 0011）

解析成果同时用于页面复核和后续编制。13 个专题仍由 DeepAgents 检索、提交和独立校验，
Agent 直接提交业务记录；展示字段由程序投影，不在报告结束后增加一轮模型转换。
本阶段提供数据和取数接口，大纲生成、正文生成与投标文件检查另行实施。

### 业务契约

`AnalysisDataset` 包含 `lots / facts / requirements / format_nodes / relations / coverage / gaps`。
模型提交 `records / coverage / gaps / research_summary / final`，记录类型为
`fact / requirement / lot / format_node / relation`。每条记录有稳定 `key`；服务端按模块命名空间
生成 `record_id`，修正同一 key 保持身份。下游固定 `snapshot_id + record_id`，不能仅凭展示标题关联。

| 内容 | 保留规则 |
| --- | --- |
| 适用范围 | `common / lots / unknown`；输入用原文 `lot_refs`，正式快照映射为 `lot_ids`；匹配不唯一则保持未知 |
| 条件 | `expression` 保留原表达；`logic` 区分 all/any/mixed/text；terms 保留主体、比较符、值、单位和起算点，exceptions 保留例外 |
| 证明材料 | `materials` 逐项保留名称和提交要求 |
| 评分 | `scoring` 保留满分、完整档次、公式和扣分；数值用字符串，避免擅自换算金额或精度 |
| 格式树 | `node_type` 区分逻辑标容器和章节；模型用 `parent_key`，服务端生成 `parent_id`，保留原文完整层级 |
| 关系 | `supersedes / conflicts / requires / contains`；端点先在同模块提交，修订和冲突同时引用双方，效力限制在双方适用范围内 |
| 验证状态 | `verification=supported` 表示原文支持；`structuring=complete/partial` 单独记录结构化程度；效力通过 `effective_status`、`superseded_in`、`conflicts_in` 表达 |

独立校验同时检查文字和业务属性，标段、比较符、分值、且或、例外不能绕过证据校验。
无法可靠拆解时保留完整原文并标记 `partial`，不推测缺失值。分批修正未通过时保留上一版已核实成果。
格式节点部分回退后重新检查累计树的循环、缺失祖先及已校验父路径；无效结构不能完成提交。
失败或取消时保留这些节点，但标记为效力未知并列入缺口，不作为下游可用格式树。
不同标段、主体、起算点或例外的同名要求分别保存；展示投影也携带 `record_id` 和适用范围说明。

标段目录仅由项目概况模块按原文提交，发布时创建或映射项目 `lot`。本报告新增的标段 ID 记录在
`derived_lot_ids`，不会因自身创建目录就被判为过期；用户改变标段分析设置仍会使报告过期。
无法映射的范围进入未决事项，不能退回公共要求，也不能默认选第一个标段。

`coverage.json` 为各模块冻结必检主题。覆盖状态包括 extracted、searched_not_found、pending、
not_applicable，以及服务端补充的 unchecked。extracted 必须关联已核实且范围吻合的记录；
某个标段完成不会代替其他标段完成。不适用结论必须独立校验并保留最终证据，读取时重新检查权限。
不适用证明的身份区分主题和范围，覆盖条目按 `review_id` 查找证明，兼容旧检查点中重复的证明 key。
未找到、未检查和检索耗尽均是缺口，不是“文件没有要求”的事实。
`final=false` 的 `gaps` 按 key 累积；`final=true` 须提交全部剩余缺口，原文和格式结构校验通过后
替换旧清单。缺口已全部解决时最终提交 `gaps=[]`；最终校验失败或中断仍保留已有缺口。

### 发布、权限与消费

报告结束且没有仍运行或最新一轮仍排队的模块后发布正式快照；失败或取消报告也可保留已核实成果。
发布在项目锁和报告行锁内执行，按运行状态及模块业务数据的 manifest 指纹幂等去重，
补跑产生变化才增加 revision。应用层只新增快照，不覆盖历史数据；模块暂存成果继续写入 `business_data`。
读取同样核对当前 manifest；取消补跑至新快照发布之间，旧快照仍标记过期并拒绝编制取数。
旧运行时报告不回填业务数据，需重新发起分析。

读取时校验完整引用身份和当前资料关联。撤销的来源即使只出现在缺口说明或不适用结论中，也会被识别；
响应隐藏相关内容并返回 `source_unavailable`，数据库历史快照保持原样。正文参考检索结束后再次校验，
不能利用检索等待期间的权限变化返回旧依据。

三种用途通过 [05-后端API设计](05-后端API设计.md) 中的 `/context` 获取“公共要求 + 一个目标标段”，
自动排除该范围的已替代和冲突要求。未知范围、结构缺口及冲突作为 `unresolved / gaps` 返回。
默认允许已核实的部分数据用于草稿，不增加整份报告人工批准的发布环节；`readiness=partial`
不能当作完整检查结论。检查用途返回完整要求清单及分页游标，正文用途额外要求明确的要求 ID。
企业与历史库片段单列为参考，不替代本次招标依据。

### 条款检索上下文（0021）

切片入库前将明确章节、编号标题、相邻正文及表格引导句组成语义大块，目标1800字符、最多12个解析片段。
知识库只存大块；检索、补读、分析及审查都使用同一大块ID和全文，不在使用时再拼接原始小块。
大块ID使用版本命名空间`s{source}r{run}g2c{ordinal}`，历史`s{source}r{run}c{ordinal}`不重新解释。
章节及A/B条款分开，跨页续文继续归属本条款，表格后的新正文另开大块。
`locations`保存入库时已经合并的大块页码、坐标及页内文字范围；模型输出摘要及必要大块ID。
同页区域使用大块的合并坐标；跨页分别保存各页区域，仍引用同一个大块ID。
最终支持性选证仅保留必要大块，摘录由代码在大块原文中匹配，原文定位直接使用大块坐标。
索引版本2不复用版本1的向量；旧索引自动安排重建，过渡期间使用同规则原文回退。
大块正文及定位区域均参与证据身份校验，防止恢复后使用失效定位。

ALTER TABLE knowledge_chunk ADD COLUMN locations JSONB;
COMMENT ON COLUMN knowledge_chunk.locations IS
'入库时合并的大块页码、坐标及页内字符范围；模型只使用大块ID';
