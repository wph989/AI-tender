# LLM管理与模型路由

管理模块维护供应商、模型、功能绑定、能力测试与调用记录。API解析参数，用例处理参数、绑定和测试规则，仓储保存配置、版本与账目；候选路由由统一工厂装配。

## 模型契约

供应商声明协议、地址和认证方式；模型声明能力与对应参数。当前语言、嵌入、重排和生图使用各自端口，参数范围与默认值由 `application/llm/profiles.py`、`registry.py` 和 `routing.py` 维护。页面读取settings生成相应表单。

功能绑定保留候选次序、不同候选上限与修订号，更新以事务和版本比较避免覆盖并发修改。模型空间身份随嵌入参数变化，知识索引必须匹配所绑定空间。

当前登记专题解析、知识问答、嵌入和重排四项功能；图片模型通过模型列表执行显式测试与预览。参数范围统一来自 `parameter_schema`，服务端校验与页面表单共用同一份定义。

## 调用与故障

模型调用记录请求状态、耗时、用量和错误；未知用量不能写成0。不同协议适配器统一转换响应与错误，429、503及断流按现有有界策略恢复，永久拒绝按明确状态码处理。

语言模型按保存的候选顺序执行。暂时故障和可纠正的协议错误使用当前模型的 `extra_retries`，每个模型最多发送 `1 + extra_retries` 次，再进入下一个候选；功能级不另设总请求上限。模块成功次数预算、总时限及不同候选上限继续约束执行。429同样使用模型重试额度，供应商冷却保持共享，不能通过切换同供应商模型绕过。尚未尝试的冷却候选可以跳过，冷却时间不用于重排候选。

页面「模型管理 → 分配功能」显示各候选的响应间隔超时和额外重试次数，点击「配置超时和重试」进入同一个模型编辑表单。`timeout_seconds` 同时约束首个有效增量等待和后续有效增量间隔，`total_timeout_seconds` 是可选的单次请求总时限。保存后新创建的模型调用读取新参数，已有调用及断点恢复沿用冻结顺序、重试额度和超时配置。

错误按模型汇总实际失败次数和去重后的上游原因，保留HTTP状态、具体超时和请求标识，先脱敏再限制超长响应。运行说明和页面详情共用真实原因，详情默认展开并保留换行。历史运行若保存的是旧通用上限提示，读取时从真实调用账还原模型错误与当时的请求上限，不改写运行审计。

模型测试是持久任务，保留开始、心跳、结束与有效期。Worker退出后结果未知的测试维持未知状态，迟到返回不能覆盖维护流程裁定。错误信息保留脱敏原因。

详细请求和响应见[API契约](05-后端API设计.md)，参数以运行settings和当前源码为准。
