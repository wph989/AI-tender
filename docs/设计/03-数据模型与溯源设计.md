# 数据模型与溯源设计

当前数据库由 `apps/api/alembic/versions/0001_current_schema.py` 一次创建。详细类型、默认值、约束和索引以基线SQL为准；ORM承担访问映射，契约测试核对类型、可空性和列名。

## 业务数据边界

- 项目关联文件和标段；文件换版产生新文档版本，解析以 `version_id` 和 `run_id` 定位。
- 文档任务持久化阶段、租约、下次执行时间及创建时预算；消息只传任务ID，重复消费通过认领和锁核对。
- 知识来源关联文件版本与解析批次；索引和引文核对来源身份，撤销关联后停止读取。
- 分析工作区保存研究、草稿和自查；最终提交原子发布模块正文，终态报告生成不可变结果快照。
- 人工裁定追加到 `analysis_record_review` 并绑定结果快照；输入和正文不匹配时裁定过期，编制只接纳当前已确认或修正的记录。
- 运行账、请求预占和调用账在事务内结算，恢复执行保留预算与租约，远端结果未知时保留未知状态。模型和工具成功计数由建库基线初始化为非空零值，在成功结算时递增；报告查询直接读取运行账。

## 溯源契约

证据保留来源、文件版本、解析批次和原文元素。页码从1开始，bbox使用左上原点的0到1归一化坐标；跨页语义块保留各页位置。前后端共享 `packages/contract/coords-vectors.json` 验证旋转与裁剪的转换规则。
