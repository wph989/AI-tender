# 当前架构与设计取舍

项目采用模块化单体：FastAPI接收请求，Celery单Worker执行文档、分析与知识任务，Beat负责投递和恢复。Worker消费 `convert,parse,tender,poll,analysis`；队列按任务用途组织，进程部署维持API＋Worker＋Beat。

## 分层与装配

`api/worker → application → ports/domain`。业务编排位于 `application/<业务>/`；数据库查询、锁及事务位于 `adapters/pg/repositories/<业务>/`；端口位于 `ports/`，具体实现由 `core/di.py` 装配。问答维护自己的提交和证据校验，分析与问答共用的检索、模型适配放在 `application/shared/`。

## 分析执行与质量

每个专题由一个Agent加载专题Skill和公共流程Skill，自主研究、保存草稿、回读、自查、修改与最终提交。程序负责预算、权限、引用身份、草稿版本和原子发布。Agent自查与人工裁定分开表达；`completed`表示本轮执行结束，`self_check_passed`表示机器自查结算通过。

工作区、不可变结果快照和追加式人工裁定承担不同生命周期：工作区可以继续修改；正式快照绑定冻结输入与正文；裁定绑定快照和记录。资料或正文变化使旧裁定过期，编制只使用当前已确认或修正的记录。

## 异步任务

持久任务表、队列派发、租约与幂等认领形成可恢复的至少一次投递。数据库提交失败、消息重复、队列不可用和执行者中断通过状态与锁恢复；外部请求结果未知时保留未知状态，不自动重提造成重复远端任务。配额释放与最终结算必须在对应事务内完成。

## 检索与存储

当前检索分块协议统一为语义块；已完成的索引直接读取数据库分块。尚未建立索引时从原文派生相同分块，支持有限窗口补读。词法评分、向量精确排名、阈值过滤、融合与返回上限在PostgreSQL执行，候选结果不返回向量。

文件存储通过同一端口选择S3或本地目录；API与Worker在启动时装配同一存储工厂。原件、PDF与解析产物沿用相同键和区间读取契约。

## 契约、健康与验证

API通过Pydantic响应模型形成OpenAPI，前端使用生成的TypeScript类型；统一检查拒绝生成文件漂移。存活探针表达进程存活，就绪探针核对PostgreSQL、Redis与所选存储。

运行 `scripts/check-backend.ps1` 验证Ruff、分层、mypy、单元/契约及OpenAPI类型。事务、锁、快照、恢复和检索改动还须运行 `scripts/check-postgres.ps1`，连接串显式指向独立测试库。数据库初始化见[17](17-数据库迁移.md)，目录规则见[21](21-后端文件树与放置规则.md)。

## 配置生效

并发、派发间隔读取实时配置；文档任务在创建时冻结执行预算；分析每次运行冻结预算，显式补跑采用当时配置。只登记已接入执行的参数，清单见[18](18-配置限制清单.md)。
