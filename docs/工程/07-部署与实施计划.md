# 07 · 部署与实施计划

## 1. 部署拓扑

```yaml
# docker-compose.yml（结构示意）
services:
  postgres:
    image: postgres:16
    volumes: [pgdata:/var/lib/postgresql/data]
    healthcheck: { test: ["CMD-SHELL", "pg_isready -U tender"], interval: 10s }

  redis:
    image: redis:7-alpine
    command: ["redis-server", "--appendonly", "yes"]

  minio:
    # 钉版本：latest 会把控制台与对象语义一起换掉（2025-05-24 起社区版控制台迁去 object-browser）
    image: ${MINIO_IMAGE:-minio/minio:RELEASE.2025-04-22T22-12-26Z}
    command: ["server", "/data", "--console-address", ":9001"]
    volumes: [miniodata:/data, minioconfig:/root/.minio]   # 配置卷放证书 / CA

  # 建桶 + 开版本化：适配器只读写对象、不建桶（见 adapters/s3.py），少了它首次上传就是 NoSuchBucket；
  # 幂等且跑完即退。换成外部对象存储时用不到：在对方那边建桶 + 开版本化即可（命令见根目录 .env.example）
  minio-init:
    image: ${MINIO_MC_IMAGE:-minio/mc:RELEASE.2025-08-13T08-35-41Z}
    depends_on: [minio]
    entrypoint: ["/bin/sh", "-c"]
    command: >
      mc alias set local http://minio:9000 "$MINIO_ROOT_USER" "$MINIO_ROOT_PASSWORD" &&
      mc mb --ignore-existing local/$S3_BUCKET && mc version enable local/$S3_BUCKET

  # Office → PDF（Gotenberg）**不在这份编排里**：它是独立部署的一条编排
  # [docker/gotenberg/docker-compose.yml]，含自建字体镜像（见 02 第 4 节）与副本入口 gotenberg-lb；
  # 单容器同一时刻只转 1 份 → 并行度 = 副本数，扩缩在那一侧做（见 02 第 5 节）

  # 文档解析：/v1/* HTTP API
  mineru:
    image: mineru:4.0.7-cu121          # 预置模型，运行时不联网
    command: >
      mineru-kit api-server --host 0.0.0.0 --port 8000
      --tier standard --api-key ${MINERU_API_KEY}
    environment:
      - MINERU_TABLE_DEVICE=auto
      - MINERU_HOME=/data/mineru
    volumes: [minerudata:/data]
    deploy:
      resources:
        reservations: { devices: [{ capabilities: [gpu] }] }   # 8G+ VRAM
    healthcheck: { test: ["CMD", "curl", "-f", "http://localhost:8000/v1/health"] }

  api:
    build: ./apps/api
    environment:
      - DATABASE_URL=postgresql+psycopg://tender:***@postgres:5432/tender
      - REDIS_URL=redis://redis:6379/0
      - S3_ENDPOINT=http://minio:9000
      - GOTENBERG_URL=http://host.docker.internal:3000   # 指向独立部署的副本入口，加副本不用改这里
      - MINERU_URL=http://mineru:8000
      - MINERU_API_KEY=${MINERU_API_KEY}
      - LLM_BASE_URL=${LLM_BASE_URL}
    depends_on: [postgres, redis, minio]

  worker:
    build: ./apps/api
    # tender 队列跑调度器任务（dispatch_pending），不能漏；漏了任务会永远停在 pending。
    # regression 队列跑管理员触发的回归回放（低优先级、与交互任务隔离；漏了回放会一直排队）
    command: ["celery", "-A", "tender.worker.celery_app", "worker", "-Q", "tender,convert,parse,extract,regression", "-c", "4"]
    environment: *api-env

  # 派发闸门：读 L1 配置 → 数在途 → 只提交差额（08 第 8 节、10 第 3.5 节）。
  # 单实例即可：多实例会各算一份差额，靠 job.dispatched_at 的 UPDATE 互斥，但不提高吞吐。
  beat:
    build: ./apps/api
    command: ["celery", "-A", "tender.worker.celery_app", "beat", "-l", "info", "--schedule", "/tmp/celerybeat-schedule"]
    environment: *api-env

  web:
    build: ./apps/web                  # Next.js，pnpm 构建
    environment: [NEXT_PUBLIC_API_BASE=/api]
```

> **可执行文件是仓库根目录的 [docker-compose.yml](../../docker-compose.yml)**：下面这段是结构示意（只讲取舍），以实际文件为准。
> **一份文件覆盖两种跑法**（`migrate / api / worker / beat / web` 都挂在 `app` profile 上）：
>
> | 目标 | 命令 | 起哪些 |
> | --- | --- | --- |
> | 只起依赖（应用在宿主机跑，默认） | `docker compose up -d` | postgres / redis / minio / minio-init / mineru |
> | 全栈（应用也进容器） | `docker compose --profile app up -d --build` | 上面这些 + migrate / api / worker / beat / web |
> | 没有 GPU 或已有独立 MinerU | 加 `--scale mineru=0` / 把 `MINERU_URL` 指过去 | 跳过 MinerU |
> | Gotenberg（Office → PDF） | 单独一份编排：`Set-Location docker/gotenberg; docker compose up -d --build` | gotenberg / gotenberg-lb（扩缩也在那一侧） |
>
> 实际文件比示意多出的部分：`migrate` 一次性跑迁移、`minio-init` 建桶并开版本化（幂等；换外部对象存储时用不到，
> 在对方那边 `mc mb` + `mc version enable` 即可）、所有端口只绑 `127.0.0.1`（由反向代理转发；web 对外 4321）、
> 以及配套的根目录 `.env.example`、`docker/gotenberg/Dockerfile`（含中文字体）与前后端 Dockerfile。
> **Gotenberg 不在根编排里，它是独立的一份**：[docker/gotenberg/docker-compose.yml](../../docker/gotenberg/docker-compose.yml)
> （LB 的 nginx 配置已内联在该文件里，只拷 `docker/gotenberg/` 一个目录；端口 / 内存 / 请求预算走那目录的 `.env.example`）。扩缩在那一侧跑
> `docker compose up -d --scale gotenberg=N`，入口统一是 `gotenberg-lb`（见 02 第 5 节），客户端 `GOTENBERG_URL` 不用改；
> 配套把配置中心的 `convert.max_inflight` 调到副本数，内存按 `副本数 × GOTENBERG_MEMORY` 估。
> 同机部署时 `GOTENBERG_URL` 用 `http://host.docker.internal:3000`（compose 的 api / worker / beat / migrate 已加
> `host.docker.internal:host-gateway` 映射，Linux 上这个域名不会自动解析），分机部署改成 `http://<主机>:3000`。

**规划要点**

- **Gotenberg 与 MinerU 都是关键路径**，必须独立健康检查与告警，不能与 api 容器混部。
- **MinerU 模型预置进镜像**：运行时无外网，杜绝模型下载失败与隐私外泄。
- **MinIO 钉版本**：默认 `RELEASE.2025-04-22T22-12-26Z`——2025-05-24 起社区版把内置 Web 控制台标记为弃用并迁到
  单独的 object-browser 项目（LDAP / OIDC 登录也移出社区版），`latest` 会让 9001 白发布；对象存储是溯源数据的
  源头，升级版本要和转换器 / 解析器一起评审（`.env` 里的 `MINIO_IMAGE` 一行即可切换）。
- **Worker 按队列拆分**：`convert`（轻、可多并发）、`parse`（重、受 GPU 数量约束）、`extract`（受 LLM 速率约束）三类队列的并发模型完全不同，混在一个队列会互相阻塞。
- 扩容策略：Gotenberg 在它自己那份编排里用 `docker compose --scale gotenberg=N` 加副本（前面有 `gotenberg-lb` 保持 URL 不变，配套调 `convert.max_inflight` 与内存）；MinerU 用 `mineru-router` 做多 GPU 编排。

### 1.1 环境配置（数据库等部署参数）

部署参数（数据库地址、外部服务地址、密钥）的取值规则只在 `apps/api/src/tender/core/settings.py` 里定义一处：

| 优先级 | 来源 | 用途 |
| --- | --- | --- |
| 1 | 真实环境变量 | 容器与 CI（就是上面 compose 里的 `environment`） |
| 2 | `apps/api/.env` | 本地开发：`cp .env.example .env` 后改。**已在 .gitignore 里，不要提交** |
| 3 | 代码里的默认值 | 让新 clone 的人能直接跑一次 `uv run alembic upgrade head` |

- **改 `.env` 立即生效，不用重启**：`settings.database_url()` 每次调用都重新取值，刻意不做模块级常量——「改了没生效」是最难查的一类问题。
- **数据库驱动是 psycopg 3**（`postgresql+psycopg://`）：同一个包既支持同步也支持异步，alembic 走同步、应用走异步都用它，不必为迁移再引第二个驱动。
- `.env` 用 `utf-8-sig` 读：Windows 记事本保存会加 BOM，带 BOM 时键名会变成 `\ufeffDATABASE_URL`，表现为「明明配了却没生效」。
- **容器编排另有一份根目录 `.env`**（同样被 .gitignore 排除）：`docker compose` 只读仓库根那一份，变量同名同义；
  两份文件服务的是两种跑法——宿主机直接跑 uvicorn/celery 用 `apps/api/.env`，容器里用根目录 `.env`。
- **业务参数不走这里**：阈值、置信度、DPI 这类要运行期即时生效、且需要审计与回滚的参数走配置中心（[08](../质量/08-动态配置中心.md)）。分界线是「重启前就定下来」还是「运行期随时改」。
- **迁移怎么跑**(执行位置、常用命令、回滚边界、新增迁移、`0008` 的 checkpoint 初始化)见 [17-数据库迁移](17-数据库迁移.md)。

## 2. 资源规划

| 服务 | CPU | 内存 | 磁盘/GPU | 说明 |
| --- | --- | --- | --- | --- |
| api | 2 核 | 2 GB | — | 编排与读写 |
| worker(convert) | 2 核 | 2 GB | — | 受 Gotenberg 能力约束 |
| worker(parse/extract) | 2 核 | 4 GB | — | 主要是 IO 等待 |
| gotenberg | 2 核/副本 | 2–4 GB/副本 | — | 大文档内存压力显著，需实测；加副本按「副本数 × 单副本」算总量 |
| mineru | 8 核 | 16 GB | GPU 8 GB+ VRAM | 官方提示 8 GB 只是规划起点 |
| postgres | 2 核 | 4 GB | 50 GB 起 | 含 element 表与文本索引 |
| minio | 2 核 | 2 GB | 按容量规划 | 原件与 PDF 基座是大头（不存页图） |

**存储估算（单份 200 页标书）**

| 项 | 估算 |
| --- | --- |
| 原件 | 5–50 MB |
| PDF 基座 | 5–50 MB |
| 多模态裁剪图（按需，仅多模态字段） | < 5 MB |
| MinerU 原始产物（含图片） | 10–80 MB |
| 元数据（element 表） | ~5 MB |

→ 按 **120 MB/份** 做容量规划，1000 份约 120 GB。原件与转换产物按哈希寻址可去重，实际占用通常更低。

## 3. 安全与保密

招标文件属敏感商业文件，以下为**强制项**：

| # | 要求 | 落地方式 |
| --- | --- | --- |
| 1 | 解析全程本地化 | MinerU 禁用 `--remote`；适配器不实现该参数 |
| 2 | 关闭遥测 | 镜像构建阶段执行 `mineru telemetry disable` |
| 3 | LLM 走内网网关 | `LLM_BASE_URL` 指向自建服务，禁止公网地址 |
| 4 | 内网隔离 | 三个外部服务均不暴露公网端口，仅容器网络可达 |
| 5 | 服务鉴权 | Gotenberg Basic Auth + MinerU `--api-key` |
| 6 | 传输加密 | 对外仅暴露 HTTPS（反向代理终止） |
| 7 | 存储加密 | MinIO 启用 SSE；数据库敏感列可选加密 |
| 8 | 下载审计 | 原件下载走短时效签名 URL + 审计日志（人/时间/版本/IP） |
| 9 | 展示水印 | 前端叠加用户名与时间水印，抑制拍照外泄 |
| 10 | 租户隔离 | 所有查询强制 `company_id` 过滤，在数据访问层实现 |
| 11 | 备份 | Postgres 每日全量 + WAL 归档；MinIO 版本化 + 跨机备份 |
| 12 | 数据留存 | 原件与解析产物按合规要求留存；删除为软删 + 定期彻底清理 |

## 4. 可观测性

| 层面 | 指标 |
| --- | --- |
| 转换 | Gotenberg 转换耗时 P95、400/500/503 比例、队列深度 |
| 解析 | MinerU 单页耗时、`partial` 比例、OOM 次数、GPU 利用率 |
| 抽取 | 字段级成功率、`not_found` 比例、校验 1/2/3 失败率、token 消耗 |
| 业务 | 平均解析耗时、人工复核率、证据命中率 |
| 溯源质量 | **证据反查 404 率**（应为 0）、bbox 为空的证据占比 |

**两个必须告警的指标**：

1. **证据反查 404 率 > 0**：说明锚点与 element 表不一致，溯源能力已破损，属最高级别告警。
2. **`page_size` 一致性断言失败**：PDF.js 视口尺寸与后端 `width_pt/height_pt` 偏差 > 1%，说明渲染基座已错位，高亮会整体漂移。

## 7. 验收标准（整体）

| 维度 | 指标 |
| --- | --- |
| **溯源完整性** | 证据反查 404 率 = **0**；每条自动结果至少有 1 条证据 |
| **定位精度** | 已渲染页点击 → 高亮可见 **< 300 ms**；高亮框与原文目视无偏移 |
| **首次通过率** | 字段**实例**级 ≥ 95%（逐条复核档）；**对外口径以随机抽检为准** |
| **人工兜底率** | ≤ 5%（最终仍需人工改值的比例） |
| **回归集不退步** | 任何配置发布后，回归集通过率不低于发布前 |
| **幻觉率** | **= 0**（无中生有的值） |
| not_found | 分布合理（人工判断），且 UI 显式可见、不隐藏 |
| 端到端耗时 | 200 页数字 PDF ≤ 5 min；200 页扫描件 ≤ 20 min |
| **可重放性** | 同一 sha256 + 同一配置快照 → 产出一致 |
| **配置即时生效** | 改动后 5 秒内全局生效，无需重启任何服务 |
| **门禁有效性** | 存在指标回退的配置无法被激活 |
