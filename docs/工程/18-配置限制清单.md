# 配置限制清单

只登记当前执行流程实际使用的23项配置。页面、写入校验和补跑预算共用 `config/schema.py` 的类型与范围。

L1运行参数按各自生命周期实时读取或冻结；L2解析选项发布前逐项确认，创建任务时冻结。配置中心按客户端提供的角色头校验操作模式。

| 参数 | 默认值 | 类型 | 范围 | 用途 |
| --- | --- | --- | --- | --- |
| `analysis.max_inflight` | `2` | int | ≥ 1 | 同公司所有报告共享的 DeepAgents 子代理并发上限 |
| `analysis.max_model_calls` | `40` | int | ≥ 1 | 每模块每次运行的成功模型请求上限，含摘要，协议失败不扣次数 |
| `analysis.max_tool_calls` | `48` | int | ≥ 1 | 每模块每次运行的成功工具执行上限 |
| `analysis.max_evidence_blocks` | `160` | int | ≥ 1 | 每模块保留的原文证据块上限 |
| `analysis.similarity_threshold` | `0.6` | number | ≥ 0，≤ 1 | 专题语义检索的最低余弦相似度（0到1）；关键词独立召回，按命中数参与融合排序 |
| `analysis.max_search_results` | `6` | int | ≥ 1 | 每次专题检索通过阈值后返回的证据块上限 |
| `analysis.rate_limit_backoff_seconds` | `30` | int | ≥ 1 | 上游429未给出恢复时间时的首次等待秒数，后续按倍数递增 |
| `analysis.rate_limit_max_wait_seconds` | `600` | int | ≥ 1 | 单个模块内为上游限流累计等待的上限秒数，超出后按可补跑失败收尾 |
| `analysis.max_subagent_retries` | `2` | int | ≥ 0 | 子Agent本地执行故障的自动恢复上限 |
| `analysis.timeout_seconds` | `1800` | int | ≥ 1 | 单个模块的总时限（非单次请求），恢复不重置 |
| `analysis.context_tokens` | `24000` | int | ≥ 1 | 模块上下文预算，达到百分之八十时压缩 |
| `analysis.max_output_tokens` | `8192` | int | ≥ 1 | 模块单次模型输出上限 |
| `convert.max_inflight` | `4` | int | ≥ 0 | 同时在途的 Gotenberg 转换请求数 |
| `parse.max_inflight` | `2` | int | ≥ 0 | MinerU 侧同时处于 queued+running 的 job 数上限，建议不超过 GPU 数 x2 |
| `dispatch.interval_seconds` | `5` | int | ≥ 1 | 调度器派发间隔；这就是配置改完多久生效的上限 |
| `job.poll.initial_interval_ms` | `2000` | int | ≥ 1 | MinerU 轮询初始间隔（毫秒） |
| `job.poll.max_interval_ms` | `30000` | int | ≥ 1 | MinerU 轮询最大间隔（毫秒） |
| `job.poll.max_attempts` | `180` | int | ≥ 1 | 轮询次数上限，超出视为超时 |
| `job.timeout.convert_minutes` | `10` | int | ≥ 1 | 转换超时（分钟） |
| `job.timeout.parse_minutes` | `60` | int | ≥ 1 | 解析超时（分钟） |
| `job.retry.convert_500` | `3` | int | ≥ 0 | Gotenberg 5xx 重试次数（400 不重试） |
| `mineru.tier` | `standard` | string | flash / basic / standard / advanced | MinerU 生产固定档；advanced 建议仅由人工对单文档触发 |
| `mineru.ocr_mode` | `auto` | string | auto / txt / ocr | 逐页自适应；扫描件占比高时可评估改 ocr |
