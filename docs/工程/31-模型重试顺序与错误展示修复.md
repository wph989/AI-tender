# 模型重试顺序与错误展示修复

更新：2026-11-26。

## 现场原因

报告2、项目1的 `project_basic_info_parsing` 运行22持续约606秒。成功模型请求25次、实际尝试35次，成功工具执行45次、实际尝试49次，模块预算分别为80次、160次和1800秒，均未达到。

最后一次逻辑模型调用 `34445318-c69b-4b01-b2ab-e4fb26dfe411` 被独立的6次请求上限截断。前3个模型各尝试2次：Qwen与nemotron发生有效增量间隔超时，step发生首个有效增量等待超时；后续minimax与Ling没有被尝试。当时模型配置都是10秒响应间隔、1次额外重试。页面的「次数或时间限制」未区分这项独立上限与模块预算，也未展示具体模型故障。

## 实现

- 复用模型的 `timeout_seconds` 和 `extra_retries`。功能候选表显示当前值并提供进入现有模型表单的按钮，定位超时输入框；候选草稿在切换与刷新时继续保留。
- 删除功能级 `max_total_requests` 字段、页面输入及执行截止。语言模型按保存顺序和各自重试额度执行，保留不同候选上限、模块成功次数和总时限。明确拒绝与本地权限错误沿用原有处理。
- 429占用一次真实尝试，等待不增加请求数。共享供应商冷却按实际恢复时间登记，包括最后一次429。模块累计等待额度或总时限容不下实际冷却时继续检查后续候选，累计值随请求窗口落库，恢复同一运行时继续使用。
- 同一专题的新逻辑请求重新读取已保存的候选配置。恢复沿用原窗口的候选顺序、超时、重试额度、请求序号和失败分类。收到失败回执后，即使取消也先完成调用账与窗口写入。
- 共享错误格式按模型归并真实失败次数和不同原因。达到总长上限时各候选保留错误摘要，较长的上游正文按剩余额度缩短。分析收尾使用统一脱敏和限长，页面默认展开并保留换行。
- 旧通用提示只在读取投影中从 `agent_model_invocation` 与 `llm_call_log` 还原。删除模型后仍按快照身份区分错误，数据库审计不变。
- 模型管理的标签容器可随页面收窄，由组件管理横向位置，避免聚焦末尾标签带动整个内容区横向滚动。窄屏可点击「更多标签」选择被收起的标签，键盘可用 End 定位末项、Enter 切换。
- ORM、API、前端生成类型、测试夹具及空库基线同步删除独立请求上限。现有数据库的旧列有默认值，当前ORM忽略该列；新机器从现行基线创建结构。

## 验证

验证覆盖5模型各2次完整候选链、不等重试次数、超过6次调用、共享429冷却、冻结窗口恢复、长错误与密钥脱敏；页面覆盖直接定位配置、保存60秒与2次额外重试、保留候选草稿。真实PostgreSQL回归核对新调用使用新配置，以及旧通用错误还原后运行审计保持一致。

统一后端检查通过1064项离线测试、五项分层、64项mypy目标和OpenAPI漂移核对。独立空库执行当前基线后，244项PostgreSQL集成测试及1项新配置读取专项通过。前端类型检查、68项单测和生产构建通过。最终生产构建的桌面和窄屏浏览器回归189项通过、1项按宽度条件跳过，覆盖「更多标签」入口、键盘切换、调用链分页和完整上游错误展示。

审查修复后的统一后端检查通过1075项离线测试，隔离 PostgreSQL 集成通过247项。新增用例覆盖读取期间解除关联、等待预算不足时切换候选、恢复后累计限流等待、同一路由器读取新配置、取消时结算失败及多个模型的错误摘要。日志为 `.cache/model-routing-review-backend.log` 和 `.cache/model-routing-review-postgres-final.log`。

上一会话核对现场任务和Worker队列为空后重启API、Worker和Beat，通过就绪检查。原报告2的运行22读取到三组真实超时原因与当时6次上限，存储审计完全一致，新设置接口已移除独立上限。模型保留原10秒配置，可在页面修改。续接验收时本地后端已停止。

验收日志在 `.cache/`，包括 `model-routing-backend-final.log`、`model-routing-postgres.log`、`model-routing-saved-interval-pg.log`、`model-routing-web-build-resumed.log`、`model-routing-resumed-focused.log` 和 `model-routing-e2e-resumed.log`。现场只读核对记录为 `model-routing-live-proof.json`。
