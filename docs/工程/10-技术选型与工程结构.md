# 技术选型与工程结构

| 层 | 当前技术 | 职责 |
| --- | --- | --- |
| 前端 | Next.js、React、TypeScript、Ant Design | 项目管理、结果复核、原文定位 |
| PDF展示 | pdfjs-dist | 浏览器渲染、文字层、归一化位置映射 |
| API | FastAPI、Pydantic | 请求与响应契约 |
| 业务 | Python用例、Agent与Skill | 文档、分析、知识、模型、配置与任务流程 |
| 持久化 | PostgreSQL、SQLAlchemy、psycopg | 事务、锁、运行账、索引与不可变快照 |
| 队列 | Redis、Celery、Beat | 消息投递、调度与恢复 |
| 文件存储 | S3或本地适配器 | 原件、PDF、解析产物及区间读取 |
| 文档转换 | Gotenberg | Office转换为PDF |
| 原文解析 | MinerU | 页面、元素、章节与位置 |

目录分为 `api`、`worker`、`application`、`domain`、`ports`、`adapters` 与 `core`。七个业务模块按既定业务组织，共用代码只放对应层的shared，装配统一在 `core/di.py`。详细放置规则见[21](21-后端文件树与放置规则.md)。

数据库基线SQL维护物理约束与索引，ORM只映射访问结构；文档表清单、ORM和基线之间有契约检查。API响应生成前端类型，生成文件漂移纳入统一后端检查。坐标规则共享JSON测试向量。

使用pnpm管理前端，依赖安装由开发者显式执行。后端验证通过已有虚拟环境运行，命令见[数据库初始化](17-数据库迁移.md)与[架构设计](11-架构设计.md)。
