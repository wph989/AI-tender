# 数据库初始化

当前版本只保留 `0001_current_schema` 空库基线，一次创建现行业务表、约束、索引和种子数据。详细结构以 `apps/api/alembic/versions/0001_current_schema.py` 为准；部署到新空库。

在 `apps/api` 目录使用已有虚拟环境执行：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m alembic upgrade head
.\.venv\Scripts\python.exe -X utf8 -m alembic current
.\.venv\Scripts\python.exe -X utf8 -m tender.adapters.pg.analysis.checkpoints
```

业务基线创建 `agent_runtime` 命名空间；检查点表由独立初始化命令建立，框架并发索引需要autocommit连接。连接配置由 `core/settings.py` 读取，环境变量 `DATABASE_URL` 优先于 `apps/api/.env`。

SQL保留数据库实际约束与索引，不能以只包含访问映射的ORM元数据替代。初始化后运行隔离PostgreSQL集成检查；结构变更同时同步ORM、基线与表清单。数据库回退使用备份恢复，不通过downgrade删除审计记录。

在项目根目录运行独立库集成验证：

```powershell
$env:TENDER_TEST_DATABASE_URL = 'postgresql+psycopg://postgres@127.0.0.1:55478/tender_baseline_test'
& .\scripts\check-postgres.ps1
```

备份和恢复使用部署方的 `pg_dump` 与 `pg_restore`；备份包含业务数据、配置、调用账及 `agent_runtime` 检查点。恢复到独立库后核对版本、表/索引、配置种子和数据量，再运行集成验证。

2026-11-22隔离验收已验证当前空库初始化及备份恢复。两个新建基线库的版本、23项配置种子、86个业务索引、7个检查点索引及41张表的列、约束和序列一致；带业务样本的恢复演练逐表核对41张表的行数和内容摘要，其中22张非空。恢复后通过当前应用读取到相同的已确认人工裁定，并由PostgreSQL检查点适配器读回相同状态。取证在本地 `.cache/current-baseline-proof.json` 和 `.cache/audit-backup-proof.json`。
