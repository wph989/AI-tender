# 商务标准解析 Skill

## 适用场景
- 触发：项目控制器启动当前专题商务标准解析任务时调用。
- 输入：授权资料清单与按需检索得到的原文块，不预先灌入全文。
- 输出：可增量暂存的 content JSON，block_ids 保留已读原文身份，由本Agent自查并明确最终提交后发布。

## 领域知识

商务标准回答“如何交易、如何履约”，仅包括：付款、交付、商务验收、质保与售后、违约责任、保险与担保、知识产权与保密、争议解决、合同变更与终止。

以下内容由其他模块输出：技术规格和功能参数、企业资格和业绩、人员要求、评分细则、投标文件格式、报价构成及项目概况。这是输出边界；公告、前附表、已填写投标函中的履约期限、条件及优先规则仍是本专题必须阅读的证据。投标保证金和履约保证金统一由保证金要求模块处理，商务标准不得重复提取。

## 识别规则

以下为章节定位和原文识别线索，选择与具体缺口有关的表达，不逐词搜索：
- "商务要求"、"合同条款"、"付款"、"交付"、"验收"
- "质保"、"售后"、"违约"、"保险"
- "知识产权"、"保密"、"争议解决"、"仲裁"、"不可抗力"

## 执行流程

1. **项目采用依据**：先用 `search_document_batch` 定位招标公告的服务/交付期限、投标人须知前附表的履约要求，以及合同文件优先顺序。读取具体填写值并记下依据ID；不能仅列文档名称就认定项目条件已经确认。
2. **专题检索与补读**：再定位商务要求、合同条款及九类履约主题，使用 `read_document` 读取相邻条款。通用条款引用投标函中的期限时，继续读取该投标函中实际填写的值。
3. **边界判断**：确认条款约束合同交易或履约，而非资格、评分、技术或报价
4. **分类整理**：同一条款只归入最相关的一类，保留期限、比例、条件和责任
5. **输出结果**：按本 Skill 的输出协议调用 submit_analysis；没有依据的条目省略。

## 取证重点与完成判断

优先定位商务要求、合同专用条款、前附表及对应补遗，按连续条款读取；一次读取可解决多个核对项。
付款、交付、验收、质保等适用条件及相互引用已核清后即可统一综合；尚缺内容明确到具体条款或材料再补查，缺失资料如实登记。

自查履约期限时，将公告或前附表已填写的期限与合同通用条款的起算机制对照；在同一条中明确本项目实际采用的期限和起算依据。不同起算点不能直接串联成一条已确认要求。
期限、起算条件不能仅检索合同章节；先取得公告和前附表对应原文再下结论。格式中的项目名称留空，不表示同一句已经填写的期限也为空；缺件记录中的“未规定/未取得”同样逐句回读核对。
付款分预付款、中期支付、费用结算逐款核对申请、发票、时限、未审批或不答复的后果、逾期责任及争议处理；一种付款的完整表述不能替代另一种付款的条件。
文件签收与工程验收分别表述。通用合同中的可选范围、建议、专用条款例外保持原有语气，不能写成已确定的项目要求。原文编号疑似错排时保留原编号并标明所在标题，不自行改成另一章的条款号。

在最终自查中明确回答：本项目已填写的服务/交付期限和起算点是什么、依据在哪里；通用条款有哪些条件或例外未在草稿保留；哪些未知参数确实只能等待附件。上述第一个问题尚未找到填写值时继续定向检索公告、前附表或已填写的投标函，不以“专用条款缺失”代替查找。

## 本项目的检索与输出

按 coverage.json 核对业务内容，保留范围、条件、例外及完整清单。工作方法遵循公共流程Skill，本文件补充本专题业务判断；工具只校验和保存数据。

## 参考文件

本Agent按公共流程Skill自主完成草稿、自查、补充、复核和最终提交；完整细则及示例可通过 read_file 查阅。

- `references/output_schema.json`：本项目机器格式声明，运行时从报告快照读取。
- `references/output_format.md`：事项组织、字段含义和实际 JSON 提交示例。
- `references/coverage.json`：本专题检索覆盖清单，未解决主题保留缺口。
- `references/<type_dir>/extraction_rules.md`：按实际品类加载的专题细则。
- `references/<type_dir>/examples.md`：模拟原文块与逐条提交样例。
type_dir 为 engineering、goods、service；只采用运行时明确的项目/标段品类，混合品类分别核对，不默认服务类。
