# 技术要求解析 Skill

## 适用场景
- 触发：主 Agent 委派技术要求解析任务时调用。
- 输入：归一化 Markdown 文件，由运行时文件清单和受限工具提供。
- 输出：技术要求结构化列表（markdown 格式），直接作为最终回复返回，由父级代码统一入库。

## 领域知识

本模块服务下游“技术方案怎么写”，只输出两类内容：项目背景、技术方案要求。

技术方案要求优先提取招标方明确划分的研究课题、专项任务、子项目或工作包，其次提取总体架构、关键技术、功能模块、接口集成、实施交付、迁移切换、运维保障、安全技术措施和风险控制。独立任务单元必须逐一保留。

商务合同、资格业绩、评分废标、格式应答、管理考核、纯承诺、人员组织、纯参数清单和知识产权程序条款必须排除。参数、功能、性能和标准只有能直接指导技术方案编写时才提取。

## 识别规则

以下为关键词种子和重点章节名；应根据文档措辞继续扩展同义词：
- "技术方案"、"技术标"、"技术建议书"、"技术规范书"
- "研究课题"、"专项任务"、"工作内容"、"子项目"、"工作包"
- "总体架构"、"关键技术"、"实施方案"、"迁移"、"运维"、"安全方案"

## 执行流程

1. **识别项目类型**：判断软件建设、工程、服务、科研或综合项目的核心技术任务
2. **定位核心章节**：检索项目背景、技术方案、技术规范、工作内容和独立任务单元
3. **扩展上下文**：读取命中章节的完整层级及相邻条款
4. **过滤边缘内容**：只保留直接回答“如何用技术、方法、工艺或服务方案实现目标”的内容
5. **按主题归并**：独立任务逐项保留，一般要求按架构、实施、保障、安全等主题归并
6. **输出结果**：按规范格式生成完整 Markdown，直接作为最终回复返回，由父级代码统一入库

## 输出规范

- 输出格式已拆分到 `references/output_format.md`。
- 执行输出前必须读取并严格遵循该文件中的专属模板和输出细节。
- 命中规则时，结果正文只能包含按专属模板整理的项目背景和技术方案要求，禁止附加解释性说明。
- 两类内容均未命中时，结果正文只能是 `无明确项目背景及技术方案要求`，禁止补充判断原因、检索过程或建议。

## 参考文件
- `references/output_format.md`：本 Skill 专属输出模板和格式约束

## 工具
- `grep`：在归一化 Markdown 中精确检索；具体路径、glob 和输出模式由运行时上下文与工具护栏约束
- `read_file`：围绕命中位置分页扩展读取上下文
- `list_extracted_files`：列出当前任务可用 Markdown 文件
- 无保存工具：模块结果直接作为最终回复返回，无相关内容也必须在最终回复正文中返回

## 注意
- 项目背景有集中原文时优先引用；无集中表述时只能基于已知事实简要归纳
- 一般技术要求允许合并概括，但不得合并或遗漏明确编号、命名的独立任务单元
- 不新增原文未要求的技术路线、产品选型或实施承诺
