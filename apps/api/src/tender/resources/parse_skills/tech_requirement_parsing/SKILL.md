# 技术要求解析 Skill

## 适用场景
- 触发：主 Agent 委派技术要求解析任务时调用。
- 输入：授权资料清单与按需检索得到的原文块，不预先灌入全文。
- 输出：submit_analysis 原生工具中的动态 JSON 条目，每条附已读取原文块的引用。

## 领域知识

本模块为技术响应核对和技术方案编写提供依据，按项目背景、技术要求组织内容。

技术方案要求优先提取招标方明确划分的研究课题、专项任务、子项目或工作包，其次提取总体架构、关键技术、功能模块、接口集成、实施交付、迁移切换、运维保障、安全技术措施和风险控制。独立任务单元必须逐一保留。

商务合同、资格业绩、评分废标、格式应答、人员组织和知识产权程序条款由其他模块处理。
明确的产品参数、功能、性能、标准、接口和检测试验要求均须保留；货物类参数表本身就是技术响应依据，不能因其不是方案叙述而排除。精确保留数值、单位、上下限、否定和星号标记，星号本身不代表否决。

## 识别规则

以下为关键词种子和重点章节名；应根据文档措辞继续扩展同义词：
- "技术方案"、"技术标"、"技术建议书"、"技术规范书"
- "研究课题"、"专项任务"、"工作内容"、"子项目"、"工作包"
- "总体架构"、"关键技术"、"实施方案"、"迁移"、"运维"、"安全方案"
- "技术参数"、"性能指标"、"规格"、"接口"、"检测"、"标准"、"★"、"▲"

## 执行流程

1. **识别项目类型**：判断软件建设、工程、服务、科研或综合项目的核心技术任务
2. **定位核心章节**：检索项目背景、技术方案、技术规范、工作内容和独立任务单元
3. **扩展上下文**：读取命中章节的完整层级及相邻条款
4. **核对技术响应**：保留参数表和方案要求，排除属于其他模块的条款；附表、脚注和参数条件一起阅读
5. **按主题归并**：独立任务逐项保留，一般要求按架构、实施、保障、安全等主题归并
6. **输出结果**：按本 Skill 的输出协议调用 submit_analysis；没有依据的条目省略。

## 输出协议

通过原生工具调用 `submit_analysis(items, relations, research_summary)` 提交结果。
每条 item 包含 kind、title、text、presentation、cells、citations；kind 可为 fact、judgment、suggestion、conflict、insufficient。
presentation 使用 paragraph、list、table；cells 为文字键值，每个表格行或列表项分别成项。
引用使用 {"block_id":"工具实际返回的块ID","quote":"块内连续原文"}；不能引用 Skill、压缩摘要或常识。
没有相关依据可提交空 items，但 research_summary 必须说明检索过的主题、缺口与不确定性。
补充文件明确修改条款时保留修改前后双方引用；参考库内容只作建议，不能替代本项目要求。

## 工具与证据

- `list_documents()`：获取本项目及关联知识库的授权资料清单。
- `search_document(query, source_id?)`：自主检索项目条款，可限定清单中的某个来源。
- `search_knowledge(query, source_id?)`：检索关联参考库，历史依据不能证明本次满足要求。
- `read_document(source_id, offset, limit)`：按命中位置扩展原文，每次最多12块；压缩后也可补读。
- `read_file(file_path)`：只读 `/skills/tech_requirement_parsing/SKILL.md` 及其 references，或会话压缩历史。
- `submit_analysis`：提交本模块综合结果和检索总结。相同命中先去重，再分析条件、例外与修订。
不进行全文顺序扫描；基于本专题问题选择检索角度，核对各份相关补充文件。

## 注意
- 项目背景有集中原文时优先引用；无集中表述时只能基于已知事实简要归纳
- 一般技术要求允许合并概括，但不得合并或遗漏明确编号、命名的独立任务单元
- 不新增原文未要求的技术路线、产品选型或实施承诺
