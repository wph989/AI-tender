# 技术要求解析 Skill

## 适用场景
- 触发：项目控制器启动当前专题技术要求解析任务时调用。
- 输入：授权资料清单与按需检索得到的原文块，不预先灌入全文。
- 输出：可增量暂存的 content JSON，block_ids 保留已读原文身份，整项审查后发布。

## 领域知识

本模块服务下游“技术方案怎么写”，只输出两类内容：项目背景、技术方案要求。

技术方案要求优先提取招标方明确划分的研究课题、专项任务、子项目或工作包，其次提取总体架构、关键技术、功能模块、接口集成、实施交付、迁移切换、运维保障、安全技术措施和风险控制。独立任务单元必须逐一保留。

商务合同、资格业绩、评分废标、格式应答、管理考核、纯承诺、人员组织、纯参数清单和知识产权程序条款必须排除。参数、功能、性能和标准只有能直接指导技术方案编写时才提取。

## 识别规则

以下为章节定位和原文识别线索，选择与具体缺口有关的表达，不逐词搜索：
- "技术方案"、"技术标"、"技术建议书"、"技术规范书"
- "研究课题"、"专项任务"、"工作内容"、"子项目"、"工作包"
- "总体架构"、"关键技术"、"实施方案"、"迁移"、"运维"、"安全方案"

## 执行流程

1. **识别项目类型**：判断软件建设、工程、服务、科研或综合项目的核心技术任务
2. **定位核心章节**：检索项目背景、技术方案、技术规范、工作内容和独立任务单元
3. **扩展上下文**：读取命中章节的完整层级及相邻条款
4. **过滤边缘内容**：只保留直接指导技术方案编写的要求；排除纯参数清单和其他维度的条款
5. **按主题归并**：独立任务逐项保留，一般要求按架构、实施、保障、安全等主题归并
6. **输出结果**：按本 Skill 的输出协议调用 submit_analysis；没有依据的条目省略。

## 取证重点与完成判断

优先定位项目背景、技术规范书、工作内容和任务附件，按连续条款读取；一次读取可解决多个核对项。
独立任务与技术方案要求的层级、条件和清单续段已核清后即可统一综合；尚缺内容明确到具体条款或材料再补查，缺失资料如实登记。

## 本项目的检索与输出

按 coverage.json 核对业务内容，保留范围、条件、例外及完整清单。研究与提交协议以运行时工具为准；本文件只定义本专题的业务判断。

## 参考文件

运行时按阶段和当前工作提供规则；尚未提供的完整细则及示例可通过 read_file 按需查阅。

- `references/output_schema.json`：本项目机器格式声明，运行时从报告快照读取。
- `references/output_format.md`：事项组织、字段含义和实际 JSON 提交示例。
- `references/coverage.json`：本专题检索覆盖清单，未解决主题保留缺口。
- `references/<type_dir>/extraction_rules.md`：按实际品类加载的专题细则。
- `references/<type_dir>/examples.md`：模拟原文块与逐条提交样例。
type_dir 为 engineering、goods、service；只采用运行时明确的项目/标段品类，混合品类分别核对，不默认服务类。
