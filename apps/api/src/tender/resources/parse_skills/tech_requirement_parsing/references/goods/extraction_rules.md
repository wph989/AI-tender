# 技术要求提取细则（goods）

以下内容是检索和判断指导，示例名词不代表本项目事实。只使用本次已读原文作依据。

只输出两类内容：项目背景、技术方案要求。所有品类都围绕投标人需要说明的技术任务和实施方法检索。
- 背景有集中表述时优先引用；分散的建设目标可据事实归纳，不补写行业背景或产品价值。
- 招标方命名、编号的课题、子项目、工作包与专项任务分别形成完整事项，不能因内容相近合并。
- 一般要求按架构、接口集成、实施迁移、运维保障、安全及风险控制归并；保留每项要求的前提和例外。
- 参数、标准、性能指标仅在约束上述方案时放入对应“关键要求”数组，保留原文数值、单位及比较符。
- 纯参数清单、产品选型表、商务合同、人员组织、评分与纯承诺不能扩展成技术方案事项。
- 不为展示章节来源而猜测标题；来源标题未读到时省略“章节来源”。

## 品类重点

检索系统集成、设备布置、接口兼容、安装调试、测试验证、迁移与运维方案。通信协议和性能阈值可作为方案约束；纯产品尺寸、重量、功率清单排除。

## 检索与自检

按上述业务主题检索项目主文件、澄清、补遗及相关附件；名称只是线索，关键词未命中不能证明全文未约定。
遇到转引继续检索目标，围绕已读 block_id 补读表头、脚注和限定条件；不能通过文件路径或推测ID读取原文。
综合前核对主体、标段、条件、单位与修订关系；无依据字段省略，未决事项保留具体缺口。
同一完整事项可以引用多个原文块；按 output_format.md 逐条提交 content JSON，原文引用独立保存。
