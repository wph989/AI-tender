# 否决条件提取细则（goods）

以下内容是检索和判断指导，示例名词不代表本项目事实。只使用本次已读原文作依据。

检索否决投标、投标无效、不予受理及资格审查结论，只有原文明确关联本次否决后果才产出事项。
- “必须、应当、不得”、★/▲标记或高风险经验仅作为检索线索，本身不能证明否决后果。
- 资格清单的后置否决结论需要补读清单范围、每项条件和结论；在证据支持其管辖范围时，将后果分别关联到独立条件。
- 独立资格条件分别保存；同一证件的名称、等级、专业和有效性构成一个完整条件，不拆散或丢失限制。
- 同条结果引用条件和后果的全部必要块。后果缺失时不生成“疑似废标”结果，也不借历史项目或法规常识补全。
- 按触发原因归入主体资格、文件形式、实质性响应、违法违规或其他废标情形，同一后果不重复归类。
- 评分扣分、一般建议、合同违约处罚与本次投标否决区分；复合条件保留且/或、例外及适用主体。

## 品类重点

候选线索包括产品认证、生产许可、制造商授权层级、检测报告时效、关键技术指标、样品及交货质保；原文未写未送样否决时，不能以“通常如此”补入。

## 检索与自检

按上述业务主题检索项目主文件、澄清、补遗及相关附件；名称只是线索，关键词未命中不能证明全文未约定。
遇到转引继续检索目标，围绕已读 block_id 补读表头、脚注和限定条件；不能通过文件路径或推测ID读取原文。
综合前核对主体、标段、条件、单位与修订关系；无依据字段省略，未决事项保留具体缺口。
同一完整事项可以引用多个原文块；按 output_format.md 逐条提交 content JSON，原文引用独立保存。
