# 废标项输出格式

## 通用返回要求
- 最终只发送一条普通 assistant 文本消息，内容为下述 Markdown 格式的结果正文。
- 正文前不得出现前言或代码围栏；正文必须是非空 Markdown，禁止空消息或只写“已完成”。
- 解析结论只输出会导致废标、否决投标、投标无效、不予受理的明确强制情形。
- 无对应内容的分类整段省略；全部无相关内容时，只输出 `无相关内容`。

```markdown

## <span style="color:#d32f2f">主体资格类</span>
| 废标情形 | 具体描述 |
|----------|----------|
|  |  |

## 投标文件形式类
| 废标情形 | 具体描述 |
|----------|----------|
|  |  |

## 实质性响应类
| 废标情形 | 具体描述 |
|----------|----------|
|  |  |

## 违法违规类
| 废标情形 | 具体描述 |
|----------|----------|
|  |  |

## 其他废标情形
| 废标情形 | 具体描述 |
|----------|----------|
|  |  |
```

## 输出细节
- 每条废标情形必须逐条列出完整内容，不得把多条条件压缩成一句概述。
- `主体资格类` 的每一行必须包含可核验的具体门槛，例如证照名称及有效性、资质类别与等级、人员资格、业绩数量与期限、财务指标或信用限制。
- “未通过资格审查将被否决”“不满足资格条件将导致废标”“资格审查不合格”等只能作为后果依据，禁止单独作为 `废标情形` 或代替资格明细。
- 当否决结论位于资格清单末尾时，必须把该结论关联到清单中的每个独立条件；表格有多少个独立资格条件，至少输出多少条对应废标情形。
- `具体描述` 必须保留原文中的主体、指标、等级、数量、期限、证件或证明材料，不得使用“满足相关要求”“详见资格条件”等指代性表述。
- 投标保证金、商务、技术和报价导致的否决情形统一按实际原因归入 `实质性响应类` 或 `投标文件形式类`。
- 分类以条款实际触发原因确定；同一情形只放入最相关的一个分类。
- 仅有评分扣分、建议性要求或一般提醒，不得写入废标项。
- 废标高风险但原文未明确否决的内容，直接排除，不写入解析结论。
