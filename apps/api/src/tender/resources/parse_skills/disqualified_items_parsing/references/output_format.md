# 废标项输出格式

## 输出协议

通过原生工具 submit_analysis 提交 fields、relations 和 research_summary，不在普通正文中模拟工具动作。
每个字段包含 `field`、`group`、`sort_order`、`values`、`note`。
`values` 是解析值数组，每个值形如 `{"value":"解析值原文表述","citations":[{"block_id":"实际读到的块ID","quote":"该块内的连续原文"}]}`，证据逐值绑定。
`group` 是展示分类（可留空），`sort_order` 是非负整数展示顺序，`note` 是备注（可留空）。
同一字段出现多个值（如不同文件或补充通知不一致）时，每个值各自成一条并带自己的引用，不合并成一段文字。
保留且/或、例外、否定、金额单位及标段条件；一个值可有多条引用。
没有相关依据返回 空 fields/relations，并填写说明检索缺口的 research_summary，不补造“未提及”记录。
参考清单只定义要核对的内容，不是另一套输出格式。文件名、页码和坐标由服务端从引用补齐。

## 内容检查清单
以下主题和字段用于检查覆盖，不要求逐项填满；只有原文明示且有引用的内容才输出。
- 解析结论只输出会导致废标、否决投标、投标无效、不予受理的明确强制情形。


## 主体资格类
- 废标情形 / 具体描述

## 投标文件形式类
- 废标情形 / 具体描述

## 实质性响应类
- 废标情形 / 具体描述

## 违法违规类
- 废标情形 / 具体描述

## 其他废标情形
- 废标情形 / 具体描述

- 每条废标情形必须逐条列出完整内容，不得把多条条件压缩成一句概述。
- `主体资格类` 的每一行必须包含可核验的具体门槛，例如证照名称及有效性、资质类别与等级、人员资格、业绩数量与期限、财务指标或信用限制。
- “未通过资格审查将被否决”“不满足资格条件将导致废标”“资格审查不合格”等只能作为后果依据，禁止单独作为 `废标情形` 或代替资格明细。
- 当否决结论位于资格清单末尾时，必须把该结论关联到清单中的每个独立条件；表格有多少个独立资格条件，至少输出多少条对应废标情形。
- `具体描述` 必须保留原文中的主体、指标、等级、数量、期限、证件或证明材料，不得使用“满足相关要求”“详见资格条件”等指代性表述。
- 投标保证金、商务、技术和报价导致的否决情形统一按实际原因归入 `实质性响应类` 或 `投标文件形式类`。
- 分类以条款实际触发原因确定；同一情形只放入最相关的一个分类。
- 仅有评分扣分、建议性要求或一般提醒，不得写入废标项。
- 废标高风险但原文未明确否决的内容，直接排除，不写入解析结论。
