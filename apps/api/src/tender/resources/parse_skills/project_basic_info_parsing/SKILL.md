# 项目基本信息解析 Skill

## 适用场景
- 触发：项目控制器启动当前专题项目基本信息解析任务时调用。
- 输入：授权资料清单与按需检索得到的原文块，不预先灌入全文。
- 输出：完成检索后按专题模板综合的 content JSON，逐条附独立的原文溯源引用。

## 领域知识

项目基本信息是招标公告、文件首页、项目概况和投标人须知前附表中的事实信息，主要包括：

1. **项目名称**：招标项目全称
2. **项目编号**：招标编号/采购编号
3. **招标人**：采购人/招标人名称
4. **招标代理机构**：代理机构名称（如有）
5. **项目事实**：地点、规模、投标截止日期、服务期限、招标范围
6. **资金与限价**：最高投标限价、资金来源、资金落实情况
7. **标段信息**：标段/包名称与编号、资质、限额、中标人数量、负责人资质

合同范本、评分标准、投标文件格式模板、技术规范和资格审查条件中的示例或占位信息必须整体排除。甲方、代理和项目字段禁止互相填充。

## 识别规则

关键词种子（可扩展，不限于），按主体分组覆盖检索：
- **甲方/代理主体**："采购人"、"招标人"、"代理机构"、"联系人"、"联系电话"、"电子邮箱"、"开户银行"、"银行账号"、"地址"
- **项目事实**："项目名称"、"项目编号"、"招标编号"、"采购编号"、"项目地点"、"项目规模"、"投标截止"、"服务期限"、"工期"、"招标范围"
- **资金与限价**："预算金额"、"最高投标限价"、"最高限价"、"资金来源"、"资金落实"
- **标段/分标**："标段"、"包号"、"包名称"、"分标资质"、"分标限额"、"中标人数量"、"中标份额"、"项目负责人资质"

## 执行流程

1. **优先检索文件头部和关键字段**：使用 `search_document` 搜索项目名称、招标编号、采购人等
2. **扩展上下文**：根据命中位置使用 `read_document` 读取前后内容
3. **排除伪来源**：跳过合同范本、评分、格式模板、技术规范及资格条件中的示例
4. **交叉核对**：按主体核对联系人和银行信息，按标段核对限价及中标份额
5. **输出结果**：按本 Skill 的输出协议调用 submit_analysis；没有依据的条目省略。

## 本项目的检索与输出

- 输入是授权资料清单及检索返回的 id/text 原文块。先核对主文件、澄清、补遗和相关附件，按 coverage.json 的业务主题继续检索；关键词只是线索，不保证完整召回。
- list_documents 返回资料ID与说明；search_document 检索本项目，search_knowledge 检索关联参考库。参考资料不能替代项目依据，参考建议也需要引用本项目相关要求。
- 遇到转引按目标名称、章节或业务主题继续检索，read_document 围绕已读 block_id 补读表头、脚注和条件；不猜测ID、磁盘路径或全文行号。未命中、缺失目标及预算不足如实登记。
- 完成主题核对后调用 complete_research，再综合同一范围内的完整事项。未命中不等于文件未约定；新增原文后重新确认检索和综合，空检索不要求重做已有事项。
- 按 output_format.md 逐条调用 submit_analysis，每次最多一条完整事项。content 承载业务内容，citations 独立提供已读ID及连续原文；不同标段或条件不强行合并。
- 全部事项处理后用空 records 和 final=true 收尾，保留未决 coverage/gaps。遇到工具错误按实际反馈和剩余额度纠正，不自行设定重试次数。
- 权限、调用预算、结构和支持性校验由运行时执行。read_file 只读取当前 Skill 的参考文件或会话历史；不读取招标文件磁盘路径，不递归委派子Agent。

## 参考文件

运行时首次推理前已加载正文、输出说明、核心细则和明确品类的规则；无需重复读取，示例按需通过 read_file 查阅。

- `references/output_schema.json`：本项目机器格式声明，运行时从报告快照读取。
- `references/output_format.md`：事项组织、字段含义和实际 JSON 提交示例。
- `references/coverage.json`：本专题检索覆盖清单，未解决主题保留缺口。
- `references/extraction_rules.md`：专题检索与判断细则。
- `references/examples.md`：模拟原文块与逐条提交样例。
