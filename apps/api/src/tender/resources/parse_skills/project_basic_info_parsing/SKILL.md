# 项目基本信息解析 Skill

## 适用场景
- 触发：主 Agent 委派项目基本信息解析任务时调用。
- 输入：授权资料清单与按需检索得到的原文块，不预先灌入全文。
- 输出：submit_analysis 原生工具提交的字段（field/group/sort_order/values/note），每个值附已读取原文块的引用。

## 领域知识

项目基本信息是招标公告、文件首页、项目概况和投标人须知前附表中的事实信息，主要包括：

1. **项目名称**：招标项目全称
2. **项目编号**：招标编号/采购编号
3. **招标人**：采购人/招标人名称
4. **招标代理机构**：代理机构名称（如有）
5. **项目事实**：地点、规模、投标截止日期、服务期限、招标范围
6. **资金与限价**：最高投标限价、资金来源、资金落实情况
7. **标段信息**：标段/包名称与编号、资质、限额、中标人数量、负责人资质

合同范本、评分标准、投标文件格式模板、技术规范和资格审查条件中的示例或占位信息必须整体排除。甲方、代理和项目字段禁止互相填充。

## 识别规则

关键词种子（可扩展，不限于），按主体分组覆盖检索：
- **甲方/代理主体**："采购人"、"招标人"、"代理机构"、"联系人"、"联系电话"、"电子邮箱"、"开户银行"、"银行账号"、"地址"
- **项目事实**："项目名称"、"项目编号"、"招标编号"、"采购编号"、"项目地点"、"项目规模"、"投标截止"、"服务期限"、"工期"、"招标范围"
- **资金与限价**："预算金额"、"最高投标限价"、"最高限价"、"资金来源"、"资金落实"
- **标段/分标**："标段"、"包号"、"包名称"、"分标资质"、"分标限额"、"中标人数量"、"中标份额"、"项目负责人资质"

## 执行流程

1. **优先检索文件头部和关键字段**：使用 `search_document` 搜索项目名称、招标编号、采购人等
2. **扩展上下文**：根据命中位置使用 `read_document` 读取前后内容
3. **排除伪来源**：跳过合同范本、评分、格式模板、技术规范及资格条件中的示例
4. **交叉核对**：按主体核对联系人和银行信息，按标段核对限价及中标份额
5. **输出结果**：按本 Skill 的输出协议调用 submit_analysis；没有依据的条目省略。

## 输出协议

通过原生工具调用 `submit_analysis(fields, relations, research_summary)` 提交结果。
每个字段包含 field、group、sort_order、values、note；values 中每个值包含 value 与 citations，证据逐值绑定。
引用使用 {"block_id":"工具实际返回的块ID","quote":"块内连续原文"}；不能引用 Skill、压缩摘要或常识。
同一字段出现多个值时每个值各自成条并带自己的引用，不合并成一段文字；一个值可有多条引用。
没有相关依据可提交空 fields，但 research_summary 必须说明检索过的主题、缺口与不确定性。
补充文件明确修改条款时保留修改前后双方引用；参考库内容只作建议，不能替代本项目要求。

## 工具与证据

- `list_documents()`：获取本项目及关联知识库的授权资料清单。
- `search_document(query, source_id?)`：自主检索项目条款，可限定清单中的某个来源。
- `search_knowledge(query, source_id?)`：检索关联参考库，历史依据不能证明本次满足要求。
- `read_document(source_id, offset, limit)`：按命中位置扩展原文，每次最多12块；压缩后也可补读。
- `read_file(file_path)`：只读 `/skills/project_basic_info_parsing/SKILL.md` 及其 references，或会话压缩历史。
- `submit_analysis`：提交本模块综合结果和检索总结。相同命中先去重，再分析条件、例外与修订。
不进行全文顺序扫描；基于本专题问题选择检索角度，核对各份相关补充文件。

## 注意
- 项目基本信息通常位于文档**开头部分**，可针对文件头部的字段检索，按命中位置补读
- 名称和编号必须**精确提取**，不得缩写或省略
- 如有标段划分，需完整提取各标段信息
- 注意区分"预算金额"和"最高限价"
- 分标限价同时写入项目最高投标限价和分标限额字段，不得用“同上”代替
