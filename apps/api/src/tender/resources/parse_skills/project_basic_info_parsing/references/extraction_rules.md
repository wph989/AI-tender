# 项目概况提取细则

以下内容是检索和判断指导，示例名词不代表本项目事实。只使用本次已读原文作依据。

检索招标公告、前附表、项目概况、标段说明与澄清文件，依据角色区分招标人、代理机构和项目。
- 名称、编号、联系方式、账号、地点及时间保留原文，不能把代理信息填入招标人信息。 <!-- topics: identity,scope,dates -->
- 工期/服务期保留起算点。 <!-- topics: scope,dates -->
- 预算与限价区分，资金来源与落实状态只在明示时输出。 <!-- topics: budget -->
- 原文明示标段或包才建立 kind=lot 记录；title 使用原文名称，code 仅在原文给出编号时填写。 <!-- topics: lots -->
- 不同标段的信息分别记录，不能塞入一个单元格或以“同上”代替各自内容；共享事项也需要共同适用依据。
- 未明确标段归属时 scope.kind=unknown；单文件、同一项目或只有一个已知标段都不自动证明 common。
- 事实片段缺失时省略对应 content 键；跨来源的主体或编号不一致先核对范围，再登记未决冲突。

## 检索与自检

按上述业务主题检索项目主文件、澄清、补遗及相关附件；名称只是线索，关键词未命中不能证明全文未约定。
遇到转引继续检索目标，围绕已读 block_id 补读表头、脚注和限定条件；不能通过文件路径或推测ID读取原文。
综合前核对主体、标段、条件、单位与修订关系；无依据字段省略，未决事项保留具体缺口。
同一完整事项可以引用多个原文块；按 output_format.md 逐条提交 content JSON，原文引用独立保存。
