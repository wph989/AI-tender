# 开标要求提取细则

以下内容是检索和判断指导，示例名词不代表本项目事实。只使用本次已读原文作依据。

检索公告、投标人须知、开标安排及变更通知，区分投标截止、开标、签到与解密时间。
- 日期、时刻、时区、地址和会议室保留原文已有精度；缺年月日或分钟不补齐，远程地址不推导为现场地点。 <!-- topics: time_place -->
- 投标截止与开标同一时刻只有原文明示才能关联，变更须引用原安排及通知。 <!-- topics: time_place -->
- 远程开标保留平台、登录、签到、解密时限、故障处理和授权代表要求，不能套用线下流程。 <!-- topics: procedure,materials -->
- 参与者身份、授权文件、携带材料及公开安排按具体事项记录；未提到法定代表人必须到场时不推定。 <!-- topics: materials -->
- 操作流程中的条件分支和超时后果完整保留，无关的文件格式和后续评标评分不收录。 <!-- topics: procedure -->
- 开标异议要将提出对象、途径、起算时点、期限和处理后果作为同一事项核对。公告或前附表已经规定线上渠道与时限时，对正文现场提出/当场答复条款逐项比较；按原文明示的优先关系保留当前有效要求。两个途径或时点不同，不能仅因都有原文就写“均保留、无冲突”；没有并行适用依据且无法确定优先时登记未决问题。 <!-- topics: procedure -->

## 检索与自检

按上述业务主题检索项目主文件、澄清、补遗及相关附件；名称只是线索，关键词未命中不能证明全文未约定。
遇到转引继续检索目标，围绕已读 block_id 补读表头、脚注和限定条件；不能通过文件路径或推测ID读取原文。
综合前核对主体、标段、条件、单位与修订关系；无依据字段省略，未决事项保留具体缺口。
草稿自查时，专门找出会推翻当前安排的候选条款：旧日期、另一地点、现场材料、互斥程序和异议方式。对每项说明采用或排除依据；发现草稿把已被替代的要求并列时，修改后再登记通过。
同一开标安排可能在公告与前附表重复出现。判断“公告与正文没有优先规则”前，回读前附表的开标程序整行（包括括号、续行、异议方式与时限），确认争议中的规定是否也写在前附表；存在时按前附表与正文的优先规则处理，不能只比较首次命中的两段。
工具返回的chapter是检索导航线索。附件标题后的正文可能被索引归在附件路径下，不能仅据此断言一整章都是独立附件；以正文标题、条号、前后文和前附表引用关系核定章节归属。
同一完整事项可以引用多个原文块；按 output_format.md 逐条提交 content JSON，原文引用独立保存。
