# 补充发现与跨文件关联

## 任务

在必检专题之外自主发现影响投标决策的重要内容，比较主文件、澄清、补遗及附件的范围和差异。
原文由检索工具按需提供 id、text，位置由服务端保管，无需访问磁盘。
本模块始终参与综合分析，不能因为有专门模块就跳过补充发现。

## 工作方法

1. 围绕补充条款、澄清、例外和跨文件差异自主检索，再按需补读其它版本和条件。
2. 查清是否同一标段、主体、时间和范围，保留且/或、例外、前提和否定。
3. 补充通知明确修改某条时同时引用原条款和修改条款；无明确关系则并列为冲突，不以上传时间裁定。
4. 未被专题覆盖的重要义务、不可抗力及关联风险可独立成项，不重复复制普通事实。
5. 补充义务、例外和已证实冲突分别形成完整事项，证据不足登记缺口；建议须引用事实前提，无依据的判断不写入解析值。
6. 仅共同出现的实体不能形成关系；关系须有直接引用及范围/条件。
7. “详见某文件/章节”“按附件执行”等指向只作线索：在授权资料中按目标名称和业务主题继续检索、补读，直接提取实际义务和条件。循环或缺失的目标登记到 complete_research 的转引清单；明确的修订关系仍可保留，不能把转引包装成补充发现。

## 本项目的检索与输出

- 输入是授权资料清单及检索返回的 id/text 原文块。先核对主文件、澄清、补遗和相关附件，按 coverage.json 的业务主题继续检索；关键词只是线索，不保证完整召回。
- list_documents 返回资料ID与说明；search_document 检索本项目，search_knowledge 检索关联参考库。参考资料不能替代项目依据，参考建议也需要引用本项目相关要求。
- 遇到转引按目标名称、章节或业务主题继续检索，read_document 围绕已读 block_id 补读表头、脚注和条件；不猜测ID、磁盘路径或全文行号。未命中、缺失目标及预算不足如实登记。
- 完成主题核对后调用 complete_research，再综合同一范围内的完整事项。未命中不等于文件未约定；新增原文后重新确认检索和综合，空检索不要求重做已有事项。
- 按 output_format.md 批量调用 submit_analysis，每次最多三条完整事项；相互独立的事项可放在同一批，有父子或端点依赖的事项分步提交。content 承载业务内容，citations 独立提供已读ID及连续原文；不同标段或条件不强行合并。
- 最后一批可携带 records 并设 final=true，通过校验即收尾；仅确认收尾时可用空 records，保留未决 coverage/gaps。遇到工具错误按实际反馈和剩余额度纠正，不自行设定重试次数。
- 权限、调用预算、结构和支持性校验由运行时执行。read_file 只读取当前 Skill 的参考文件或会话历史；不读取招标文件磁盘路径，不递归委派子Agent。

## 参考文件

运行时首次推理前已加载正文、输出说明、核心细则和明确品类的规则；无需重复读取，示例按需通过 read_file 查阅。

- `references/output_schema.json`：本项目机器格式声明，运行时从报告快照读取。
- `references/output_format.md`：事项组织、字段含义和实际 JSON 提交示例。
- `references/coverage.json`：本专题检索覆盖清单，未解决主题保留缺口。
- `references/reduce_strategy.md`：跨文件归并及冲突判断。
- `references/retry_policy.md`：运行时错误反馈和收尾说明。
