# 评分标准解析 Skill

## 适用场景
- 触发：项目控制器启动当前专题评分标准解析任务时调用。
- 输入：授权资料清单与按需检索得到的原文块，不预先灌入全文。
- 输出：完成检索后按专题模板综合的 content JSON，逐条附独立的原文溯源引用。

## 领域知识

评分标准是招标文件中规定评标方法和分值分配的核心内容，主要包括：

1. **评标方法**：综合评分法、最低评标价法、性价比法等
2. **分值分配**：技术分、商务分、价格分的权重和分值
3. **评分细则**：每个评分项的评分标准（满分条件、扣分规则）
4. **价格分计算**：基准价确定方法、价格分计算公式
5. **加分/扣分项**：优惠政策、中小企业加分等

有效评分标准必须包含具体分值、计算公式或“评分项+评分细则”结构。仅有评标流程、资格/符合性审查、目录索引、供应商绩效考核、项目验收评分、合同条款或文件格式要求时不得提取。

## 识别规则

以下为关键词种子和重点章节名；应根据文档措辞继续扩展同义词：
- "评标办法"、"评标方法"、"评分标准"、"评分细则"
- "综合评分法"、"最低评标价法"
- "分值"、"权重"、"得分"
- 分值表格
- "价格分"、"技术分"、"商务分"

## 执行流程

1. **主题检索**：使用 `search_document` 搜索"评标办法""评分标准"等章节标题
2. **展开转引与上下文**：命中“详见第三章/某附件”“按前附表执行”等指向时，用文件名、章节名、条号加评分主题继续 `search_document`；跨文件先 `list_documents` 确认授权资料并限定 source_id。命中目标后用 `read_document` 补读评分表、表头、脚注和相邻条件；目录或转引句只作线索，不作评分结果
3. **有效性判断**：确认存在分值、公式或实质评分细则
4. **先总后细**：先提取评标方法、总分构成和总体公式，再完整提取评分表
5. **层级校验**：区分总分、评分项和评分档次；评分档次不得重复计为独立评分项
6. **结构选择**：原文分开商务/技术时分别输出，合并时输出综合评分
7. **输出结果**：按本 Skill 的输出协议调用 submit_analysis；没有依据的条目省略。

遇到多级转引继续追踪到实际规则；同一指向循环、目标文件未提供或预算耗尽时，将追踪路径和缺口写入 research_summary，不以“详见……”占位，不以历史资料或常识补齐。

## 本项目的检索与输出

- 输入是授权资料清单及检索返回的 id/text 原文块。先核对主文件、澄清、补遗和相关附件，按 coverage.json 的业务主题继续检索；关键词只是线索，不保证完整召回。
- list_documents 返回资料ID与说明；search_document 检索本项目，search_knowledge 检索关联参考库。参考资料不能替代项目依据，参考建议也需要引用本项目相关要求。
- 遇到转引按目标名称、章节或业务主题继续检索，read_document 围绕已读 block_id 补读表头、脚注和条件；不猜测ID、磁盘路径或全文行号。未命中、缺失目标及预算不足如实登记。
- 完成主题核对后调用 complete_research，再综合同一范围内的完整事项。未命中不等于文件未约定；新增原文后重新确认检索和综合，空检索不要求重做已有事项。
- 按 output_format.md 逐条调用 submit_analysis，每次最多一条完整事项。content 承载业务内容，citations 独立提供已读ID及连续原文；不同标段或条件不强行合并。
- 全部事项处理后用空 records 和 final=true 收尾，保留未决 coverage/gaps。遇到工具错误按实际反馈和剩余额度纠正，不自行设定重试次数。
- 权限、调用预算、结构和支持性校验由运行时执行。read_file 只读取当前 Skill 的参考文件或会话历史；不读取招标文件磁盘路径，不递归委派子Agent。

## 参考文件

运行时首次推理前已加载正文、输出说明、核心细则和明确品类的规则；无需重复读取，示例按需通过 read_file 查阅。

- `references/output_schema.json`：本项目机器格式声明，运行时从报告快照读取。
- `references/output_format.md`：事项组织、字段含义和实际 JSON 提交示例。
- `references/coverage.json`：本专题检索覆盖清单，未解决主题保留缺口。
- `references/<type_dir>/extraction_rules.md`：按实际品类加载的专题细则。
- `references/<type_dir>/examples.md`：模拟原文块与逐条提交样例。
type_dir 为 engineering、goods、service；只采用运行时明确的项目/标段品类，混合品类分别核对，不默认服务类。
