# 格式层级与逻辑标识别

## 先理解角色再建层级

按同一资料补读得到的正文顺序记录名称、管辖范围和并列/包含关系。候选主要角色是逻辑标类型、具体材料章节或说明正文，不能同时充当容器和章节。

- 逻辑标类型分别领起后续一组材料，具有独立组织作用。
- 章节命名实际需要编制、填写、证明或响应的材料，即使带子章节也可为具体材料。
- 说明正文陈述填写方法和条款要求，不自动成为结构节点。

分册、装订、单独密封是补充证据，不是标类型存在的必要条件。一句“商务部分、技术部分、其他文件”的罗列不能证明分别领起章节的容器。
“商务偏离表”是具体表单；独立“商务部分”实际统领业绩、人员等章节时才可为容器。这些例子不能变成关键词名单。

## 管辖关系与层级

1. 先识别容器至下一个同级容器前的区段，再在区段内判断章节关系。
2. 容器之前的独立材料不能倒挂到后面容器下，按游离章节保留。
3. 依概括范围、并列和父子关系建立一级至三级章节，编号、长度、后缀不能单独决定层级。
4. 顶层节点若只组织材料而自身不命名需要编制的具体内容，应转为逻辑标容器，其子章节从一级开始。
5. 超过三级的内容归入有效上级的编制要求；独立实质条件可另列带引用条目，不能丢弃。
   已明确命名且处于三级以内的子材料各自成为 section 节点；不能用父节点的 requirements 代替这些子节点。
6. 不同文件不能仅凭同名建立父子关系，关联须有直接依据。
7. 附件要求单独提交且没有明示所属标或父章节时，按独立章节保留；不能只因紧跟某个标的正文就归入该标。

## 原文与证据

标题复制同一块的连续原文，不跨块拼接。排版将说明和标题合在一块时，只有上下文支持语义切换才截取连续标题片段，仍引用真实块。
同块含明确材料清单可逐项提取名称，各项分别引用支持原文。节点的标类型、上级路径和编制要求都应有证据，必要时附多处引用。
每节点提供覆盖自身名称和要求的连续引文。程序按唯一父路径汇集各祖先节点的已校验引文，形成完整归属判断的证据；无需在每个子节点重复抄写祖先原文，不能跨段拼接成不存在的连续引文。
汇集引用不等于证明层级，仍须核对原文是否支持父子归属；证据仅是同块出现或位置相邻时，不建立包含关系。
目录可帮助查找，最终节点以实际展开的正文为依据。已经排除的导航目录不再作为节点的最终引用。
输出前核对遗漏并列容器、前置章节倒挂、跨区段吸附、目录重复及名称改写。
最终用 output_format.md 的扁平节点数组提交唯一父级；程序生成动态表格的层级、父路径和关系，不另写第二套归属描述。
