# 章节树语义提取规则

## 任务

从已定位并排除导航目录、图片和表格占位符的正文中，理解每个文本元素的结构角色，提取真实标类型和 1-3 级章节树。

标类型是逻辑组织分组，不等同于物理分册。单册装订不能否定标类型；分册提交、分别装订或单独密封只能作为补充证据，不能成为必要条件。

## 分阶段提取过程

1. 按 index 建立候选清单，先记录原文、直接管辖范围以及与前后候选的并列或包含关系，暂不赋最终 level。
2. 先从候选中识别逻辑标类型，确定每个标类型从自身之后到下一个同级标类型之前的连续管辖区段。
3. 再分别处理各标类型区段和游离章节区段，不跨区段寻找父节点。
4. 在区段内部根据概括范围、并列关系和实际管辖内容构建 1-3 级章节树。
5. 最后回到整个目标范围，检查并列标类型遗漏、前置章节倒挂、区段结束后的错误吸附和游离分组节点。

禁止先把所有候选直接做成章节树后结束；即使初步树看似完整，也必须完成标类型识别和全文回看。

## 禁止机械分类

- 禁止建立标类型、标题或正文的关键词黑白名单。
- 禁止把某种编号固定映射到某一级标题。
- 禁止根据名称后缀、文本长度、是否带编号或是否独立成行直接分类。
- 禁止把下面的例子扩展为穷举规则。

模型应理解文本中心含义、它与前后内容的关系，以及它在整个投标文件组织中的实际作用。

## 原文与 index

- `element_index` 和 `package_type_index` 必须使用工具返回的真实 index。
- 标题和标类型名称默认完整复制同一元素的 `text`。
- 不得改写、概括、规范化标点或跨元素拼接。

### 复合元素

Word 排版可能把上一段说明和下一标题保存在同一元素中。只有当上下文清楚表明元素内部发生了语义角色切换，并且后半部分与附近结构形成一致关系时，才允许截取连续原文片段作为标题，同时沿用原 index。

例如，一个元素前半部分结束上一项说明，后半部分开始一个新的附件标题；此时只提取连续的附件标题原文。该例说明语义边界处理，不代表附件一定是标题，也不提供固定切分词。

## 互斥角色判断

对每个正文元素结合上下文判断其唯一角色：

1. **标类型容器**：全文要求投标文件按它形成独立的顶层组织单元，并且它实际统领后续一组章节。
2. **章节标题**：给投标人需要编制的某类内容或某份具体材料命名，并在章节树中承担结构节点作用。
3. **说明正文**：陈述要求、解释填写方式、引用其他条款或补充说明，不开启新的结构节点。

同一元素不能同时作为标类型和章节输出。无法确认是标类型时，应按整体结构重新理解；仍无充分依据则不要创建标类型。

## 标类型的语义判断

标类型不是“看起来像分类名称”的文本，而是投标文件实际组织方式中的顶层容器。综合判断：

- 后续哪些章节受它共同管辖；
- 何处出现与它并列的另一个顶层容器；
- 全文关于编制、装订、提交和组织方式的说明是否支持这种划分；
- 这种解释能否覆盖目标范围且不造成前置章节无处归属或章节倒挂。

若某文本中心含义是一份具体表单或附件，即使名称中包含分类概念，也仍是章节标题。

### 顶层章节反查

初步章节树不是最终分类依据。建树后必须反查每个顶层节点，尤其是带有子节点的顶层节点：

1. 暂时移除该节点，观察其直属子节点是否是一组可直接编制、填写或提交的具体材料；
2. 判断该节点自身是否也命名一份需要单独编制的材料，还是只概括并组织这些子节点；
3. 如果移除它不会丢失具体材料，只会失去这组材料的上位分组名称，它就是标类型容器；
4. 如果它自身就是需要编制的方案、表单、函件或其他具体内容，即使带有子节点，仍是章节标题。

初步输出为 `level=1` 不能作为保留章节角色的依据。确认是标类型后，将该节点移入 `package_types`，使用其原始 `element_index` 作为 `package_type_index`，原 `children` 作为 `chapters`，并按移除容器后的真实章节关系重新从 `level=1` 编排。

简单校准示例：

- 两个并列名称分别统领不同章节组，全文也把它们作为独立编制单元：可以理解为两个标类型。
- “商务部分偏离表”的中心含义是具体表单：应理解为章节标题。
- 独立出现的“商务部分”若实际统领“类似业绩”等一组具体材料章节，其中心作用是组织分组：应理解为标类型；“类似业绩”成为该标类型下的 `level=1` 章节。这里依据的是统领关系，不是“商务”或“部分”等词。
- 资格、技术、商务等名称只是在同一句或同一段中并列罗列（如“投标文件包括商务部分、技术部分、其他文件”）：这是正文描述，不是标类型。
- 资格、技术、商务等名称分别出现在不同位置、各自领起后续一组章节：应理解为各自独立的标类型。

## 标题与正文的语义判断

判断文本是否在“给结构命名”：

- 它是否概括后续内容，或者命名一份投标人实际需要编制的材料；
- 前后是否存在与它语义范围相当的并列节点；
- 后续内容是否受它管辖，直到另一个同级节点出现；
- 将它视为标题后，整棵树是否比视为普通说明更连贯。

说明句可能包含材料名称，标题也可能没有后续说明。不要以句式、长度、编号或是否有正文作为单独依据。

## 标题层级的语义判断

先理解局部结构，再赋予 `level`：

1. 比较每个标题概括的内容范围，范围更大的节点通常更接近树根。
2. 比较相邻标题是否并列，或是否明显属于前一个标题的细分。
3. 确认父节点能够合理统领所有子节点，并在下一个同级节点出现时结束管辖。
4. 观察文档自己的编号体系来验证关系，但不得把编号样式直接翻译成固定层级。
5. 若缺少合理父级，重新理解上下文，不要机械提升或降级。

例如，一个概括商务材料的标题统领业绩、人员和承诺等多个具体材料时，前者应处于较高层；某张具体表单通常处于其下级。例子只说明概括范围与父子关系，不限定名称。

## 构建章节树

1. 按真实 index 顺序处理已经完成语义分类的节点。
2. 标类型只管辖出现在它之后、下一个同级标类型之前，且语义上确实归属于它的章节。
3. 归属某标类型的章节 index 都必须大于该标类型的 index。
4. 某标类型之前已有无法合理归属的独立章节时，不要倒挂到该标类型下；这类顶层游离章节直接放入 `items`。
5. 根据已判断的父子关系构建 1-3 级树；更深节点不单独输出，但保留有效上级。
6. 归属标类型的章节放入对应 `chapters`；不隶属任何标类型的顶层章节放入 `items`。`package_types` 与 `items` 可以同时非空。

## 输出前自检

- 每个标类型是否确实是分别领起各自章节组的顶层组织容器，而不是内容分类罗列、正文描述或具体材料？
- `items` 中是否仍有只负责组织子章节、自身不命名具体材料的顶层节点？若有，必须移入 `package_types` 并重排子树 level。
- 每个标题是否真的承担结构命名功能，而不是说明或引用？
- 每个层级是否由概括范围、父子关系和并列关系共同支持？
- 是否因某个词、编号、长度或位置做了直接分类？若是，必须重新判断。
- 标题树是否按原文顺序、真实 index 和合理管辖范围构建？
- 所有标题是否保持原文，且最终节点不超过三级？

最终节点只包含 `title`、`level`、`element_index`、`children`；标类型只包含 `name`、`package_type_index`、`chapters`。
