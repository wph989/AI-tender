# 目录语义过滤规则

## 任务

在已定位的投标文件格式正文范围内，判断哪些连续文本只承担导航或索引功能，并在建树前排除这些元素。

## 核心原则

目录是“功能角色”，不是某种固定文本外观。禁止用预设名称、页码形式、段落数量、字符长度、编号模式或所在位置单独决定目录属性。

## 判断方法

结合一组连续元素的上下文判断：

1. 这些文本是在向读者展示后续内容的组织关系，还是已经开始规定投标人要填写、提交或响应的实际内容？
2. 每个条目是否只提供导航信息，后文是否再次出现并展开同一结构？
3. 该区域内部是否主要由名称之间的层级关系构成，而缺少实际编制说明、模板内容或材料要求？
4. 排除该区域后，正文结构是否更连贯；若保留它，是否会造成同一批章节重复出现？

页码、连续短行、相似编号或位于章节开头都可以帮助理解，但只能作为上下文证据，不能成为判定条件。

## 区域判断

- 以完整目录区域为单位判断，不要只因某一行像标题就单独删除。
- 找到导航功能开始和结束的位置，再整体排除其中的目录条目。
- 正文中连续出现多个短标题并不必然是目录；若这些标题已经对应实际模板或编制内容，应保留。
- 判断不确定时优先保留，避免误删真实章节；后续可通过是否重复展开再次验证。

## 简单示例

- 一组文本只展示章节关系，后文再次逐项出现并附有具体内容：前一组是目录，后一组是正文。
- 多个材料名称连续出现，但每个名称后立即进入填写或提交内容：这是正文结构，不应按目录删除。

示例只用于说明“导航功能”和“正文功能”的差异，不构成格式匹配规则。

## 本项目中的处理

目录仅用于定位线索，不调用额外工具提交目录索引数组。
继续检索实际格式正文并按已读ID补读；不能确认材料或归属时登记缺口，不用目录标题生成无依据节点。
