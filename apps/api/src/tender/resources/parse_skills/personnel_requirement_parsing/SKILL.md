# 人员要求解析 Skill

## 适用场景
- 触发：项目控制器启动当前专题人员要求解析任务时调用。
- 输入：授权资料清单与按需检索得到的原文块，不预先灌入全文。
- 输出：可增量暂存的 content JSON，block_ids 保留已读原文身份，整项审查后发布。

## 领域知识

人员要求是对投标人拟投入本项目的具体岗位人员提出的可操作要求，主要包括：

1. **项目经理/负责人**：资质等级、从业年限、类似项目经验
2. **技术负责人**：职称、专业背景、资格证书
3. **其他关键岗位**：安全员、质量员、施工员等
4. **人员数量**：各岗位的最低人数要求
5. **社保证明**：是否需提供社保缴纳证明
6. **不得兼任**：哪些岗位不得由同一人兼任

候选条款必须满足：主语是具体人员或岗位，且至少包含人数、个人证书/职称/学历、明确年限或针对个人属性的量化评分之一。仅出现岗位名称、团队配置合理等模糊表述不得提取。

必须排除企业资质/认证、企业业绩、企业持有证书数量、报价与商务条款、投标文件格式、中标后抽测，以及人员行为规范、稳定性、管理制度、服务态度和责任承担等软性要求。要求提供社保、劳动合同等证明材料时可以提取，但一般性的依法缴纳社保不得提取。

## 识别规则

可选定位线索（无需逐词查询）："人员"、"项目经理"、"技术负责人"、"配备"、"团队"、"人员配置"

## 执行流程

1. **主题检索**：使用 `search_document_batch` 搜索"人员""项目经理"等章节
2. **扩展上下文**：根据命中位置使用 `read_document` 读取相邻条款
3. **主语判定**：回答“投标人是否需要为此安排一个具体的人”，否则排除
4. **逐岗位归并**：提取数量、评分、个人证书、经验、专业、技能、证明和兼任限制
5. **输出结果**：按本 Skill 的输出协议调用 submit_analysis；没有依据的条目省略。

## 取证重点与完成判断

优先定位资格条件、项目人员要求、人员评分项和证明材料附件，按连续条款读取；一次读取可解决多个核对项。
岗位、人数、资质、经历、在岗条件、证明材料及评分用途已核清后即可统一综合；尚缺内容明确到具体条款或材料再补查，缺失资料如实登记。

## 本项目的检索与输出

按 coverage.json 核对业务内容，保留范围、条件、例外及完整清单。研究与提交协议以运行时工具为准；本文件只定义本专题的业务判断。

## 参考文件

运行时按阶段和当前工作提供规则；尚未提供的完整细则及示例可通过 read_file 按需查阅。

- `references/output_schema.json`：本项目机器格式声明，运行时从报告快照读取。
- `references/output_format.md`：事项组织、字段含义和实际 JSON 提交示例。
- `references/coverage.json`：本专题检索覆盖清单，未解决主题保留缺口。
- `references/<type_dir>/extraction_rules.md`：按实际品类加载的专题细则。
- `references/<type_dir>/examples.md`：模拟原文块与逐条提交样例。
type_dir 为 engineering、goods、service；只采用运行时明确的项目/标段品类，混合品类分别核对，不默认服务类。
