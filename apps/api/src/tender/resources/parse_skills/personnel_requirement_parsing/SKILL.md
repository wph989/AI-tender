# 人员要求解析 Skill

## 适用场景
- 触发：主 Agent 委派人员要求解析任务时调用。
- 输入：归一化 Markdown 文件，由运行时文件清单和受限工具提供。
- 输出：人员要求结构化文档（markdown 格式），直接作为最终回复返回，由父级代码统一入库。

## 领域知识

人员要求是对投标人拟投入本项目的具体岗位人员提出的可操作要求，主要包括：

1. **项目经理/负责人**：资质等级、从业年限、类似项目经验
2. **技术负责人**：职称、专业背景、资格证书
3. **其他关键岗位**：安全员、质量员、施工员等
4. **人员数量**：各岗位的最低人数要求
5. **社保证明**：是否需提供社保缴纳证明
6. **不得兼任**：哪些岗位不得由同一人兼任

候选条款必须满足：主语是具体人员或岗位，且至少包含人数、个人证书/职称/学历、明确年限或针对个人属性的量化评分之一。仅出现岗位名称、团队配置合理等模糊表述不得提取。

必须排除企业资质/认证、企业业绩、企业持有证书数量、报价与商务条款、投标文件格式、中标后抽测，以及人员行为规范、稳定性、管理制度、服务态度和责任承担等软性要求。要求提供社保、劳动合同等证明材料时可以提取，但一般性的依法缴纳社保不得提取。

## 识别规则

关键词种子（可扩展，不限于）："人员"、"项目经理"、"技术负责人"、"配备"、"团队"、"人员配置"

## 执行流程

1. **精确检索**：使用 `grep` 搜索"人员""项目经理"等章节
2. **扩展上下文**：根据命中位置使用 `read_file` 读取相邻条款
3. **主语判定**：回答“投标人是否需要为此安排一个具体的人”，否则排除
4. **逐岗位归并**：提取数量、评分、个人证书、经验、专业、技能、证明和兼任限制
5. **输出结果**：按规范格式生成完整 Markdown，直接作为最终回复返回，由父级代码统一入库

## 输出规范

- 输出格式已拆分到 `references/output_format.md`。
- 执行输出前必须读取并严格遵循该文件中的专属模板和输出细节。
- 命中规则时，结果正文只能包含按专属模板整理的具体岗位人员要求，禁止附加解释性说明。
- 未命中任何符合本 Skill 判定条件的岗位人员要求时，结果正文只能是 `无相关内容`，禁止补充排除原因、检索过程或建议。

## 参考文件（按标类型加载）
根据当前项目的标类型（bid_type），加载对应子目录下的参考文件：
- `references/output_format.md`：本 Skill 专属输出模板和格式约束
- `references/<type_dir>/extraction_rules.md`：逐岗位提取规则、社保要求、兼任限制、严禁行为、自检清单
- `references/<type_dir>/examples.md`：完整人员配置要求提取样例
- bid_type 取值：service（服务类）、engineering（工程类）、goods（货物类）
- 如无法确定标类型，默认加载 service 目录

## 工具
- `grep`：在归一化 Markdown 中精确检索；具体路径、glob 和输出模式由运行时上下文与工具护栏约束
- `read_file`：围绕命中位置分页扩展读取上下文
- `list_extracted_files`：列出当前任务可用 Markdown 文件
- 无保存工具：模块结果直接作为最终回复返回，无相关内容也必须在最终回复正文中返回

## 注意
- 人员资质要求需区分"强制性"和"加分项"
- 注意证书的有效期和等级要求
- 注意社保证明的时间要求
- 同时存在总人数和细分岗位时，以细分岗位为主，并将总人数写入相关岗位备注
