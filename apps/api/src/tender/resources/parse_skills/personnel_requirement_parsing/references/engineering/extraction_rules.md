# 人员要求提取细则（engineering）

以下内容是检索和判断指导，示例名词不代表本项目事实。只使用本次已读原文作依据。

按原文岗位及适用范围提取人员数量、证书、经验、社保与评分要求，不凭行业惯例补齐岗位。
- 名称不同但职能相同的岗位只有在条件和范围一致时才归并，“包含岗位”保留原文名称。 <!-- topics: roles -->
- 证书名称、专业、等级、有效期、注册单位与证明材料分别核对；企业证书和企业业绩不转成人员要求。 <!-- topics: qualification,materials -->
- 人数、驻场时间、劳动关系和社保月份保留原文口径，不按团队总数推算每个岗位人数。 <!-- topics: quantity,materials -->
- 兼任限制保留岗位组合、数量上限及“含本项目”等边界，不能把“最多3项”改成“不足3项”。 <!-- topics: roles,quantity -->
- 同一岗位的不同标段、资格门槛和评分条件不能混为一个无范围的条目；个人业绩保留本人角色和认定节点。 <!-- topics: qualification,experience,scoring -->
- 至少有数量、个人资格或人员评分依据才输出岗位；团队整体方案评价不属于人员要求。

## 品类重点

岗位线索包括项目经理、技术负责人、安全员、总监理工程师；建造师专业等级、B/C证、职称、社保和在建限制均需原文依据，不能自动补齐证书组合。

## 检索与自检

按上述业务主题检索项目主文件、澄清、补遗及相关附件；名称只是线索，关键词未命中不能证明全文未约定。
遇到转引继续检索目标，围绕已读 block_id 补读表头、脚注和限定条件；不能通过文件路径或推测ID读取原文。
综合前核对主体、标段、条件、单位与修订关系；无依据字段省略，未决事项保留具体缺口。
同一完整事项可以引用多个原文块；按 output_format.md 逐条提交 content JSON，原文引用独立保存。
