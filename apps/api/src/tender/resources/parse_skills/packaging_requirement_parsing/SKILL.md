# 封装要求解析 Skill

## 适用场景
- 触发：主 Agent 委派封装要求解析任务时调用。
- 输入：归一化 Markdown 文件，由运行时文件清单和受限工具提供。
- 输出：封装要求结构化文档（markdown 格式），直接作为最终回复返回，由父级代码统一入库。

## 领域知识

封装要求是招标文件中对投标文件制作和提交形式的规定，主要包括：

1. **份数要求**：正本/副本各需几份
2. **密封要求**：密封方式、密封袋要求
3. **标记要求**：封面标注内容（项目名称、编号、投标人等）
4. **分册要求**：技术标/商务标/价格标是否分开封装
5. **电子版要求**：U盘/光盘、文件格式
6. **装订要求**：胶装/活页、页码编排
7. **组成与签章**：文件组成、签字人资格、盖章位置和类型

本模块提取具体制作与提交要求，不提取投标文件格式大纲的章节树结构，也不把技术、商务或资格内容本身当作格式要求。

## 识别规则

关键词种子（可扩展，不限于）："封装"、"密封"、"装订"、"正本"、"副本"、"份数"、"标记"、"包装"

## 执行流程

1. **精确检索**：使用 `grep` 搜索"封装""密封""装订"等章节
2. **扩展上下文**：根据命中位置使用 `read_file` 读取相邻条款
3. **提取要求**：提取组成、格式、签章、密封、份数、纸质版和电子版要求
4. **输出结果**：按规范格式生成完整 Markdown，直接作为最终回复返回，由父级代码统一入库

## 输出规范

- 输出格式已拆分到 `references/output_format.md`。
- 执行输出前必须读取并严格遵循该文件中的专属模板和输出细节。
- 命中规则时，结果正文只能包含按专属模板整理的实际解析结果，禁止附加解释性说明。
- 未命中任何封装或投标文件制作要求时，结果正文只能是 `无相关内容`，禁止补充未命中原因、检索过程或建议。

## 参考文件
- `references/output_format.md`：本 Skill 专属输出模板和格式约束
- `references/extraction_rules.md`：分册/密封/标记/电子版提取规则、盲标处理、严禁行为、自检清单
- `references/examples.md`：完整封装要求提取样例

## 工具
- `grep`：在归一化 Markdown 中精确检索；具体路径、glob 和输出模式由运行时上下文与工具护栏约束
- `read_file`：围绕命中位置分页扩展读取上下文
- `list_extracted_files`：列出当前任务可用 Markdown 文件
- 无保存工具：模块结果直接作为最终回复返回，无相关内容也必须在最终回复正文中返回

## 注意
- 封装要求是废标高频区域，必须**完整提取**
- 注意区分"正本"和"副本"的不同要求
- 注意电子标和纸质标的差异
