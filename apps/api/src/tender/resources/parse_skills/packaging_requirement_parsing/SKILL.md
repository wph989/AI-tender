# 封装要求解析 Skill

## 适用场景
- 触发：项目控制器启动当前专题封装要求解析任务时调用。
- 输入：授权资料清单与按需检索得到的原文块，不预先灌入全文。
- 输出：研究结束后统一综合的 content JSON，逐条附独立的原文溯源引用。

## 领域知识

封装要求是招标文件中对投标文件制作和提交形式的规定，主要包括：

1. **份数要求**：正本/副本各需几份
2. **密封要求**：密封方式、密封袋要求
3. **标记要求**：封面标注内容（项目名称、编号、投标人等）
4. **分册要求**：技术标/商务标/价格标是否分开封装
5. **电子版要求**：U盘/光盘、文件格式
6. **装订要求**：胶装/活页、页码编排
7. **组成与签章**：文件组成、签字人资格、盖章位置和类型

本模块提取具体制作与提交要求，不提取投标文件格式大纲的章节树结构，也不把技术、商务或资格内容本身当作格式要求。

## 识别规则

可选定位线索（无需逐词查询）："封装"、"密封"、"装订"、"正本"、"副本"、"份数"、"标记"、"包装"

## 执行流程

1. **主题检索**：使用 `search_document` 搜索"封装""密封""装订"等章节
2. **扩展上下文**：根据命中位置使用 `read_document` 读取相邻条款
3. **提取要求**：提取组成、格式、签章、密封、份数、纸质版和电子版要求
4. **输出结果**：按本 Skill 的输出协议调用 submit_analysis；没有依据的条目省略。

## 取证重点与完成判断

优先定位前附表、投标文件编制与递交章节，按连续条款读取；一次读取可解决多个核对项。
正副本、份数、装订、密封标记及电子提交的适用条件已核清后即可统一综合；尚缺内容明确到具体条款或材料再补查，缺失资料如实登记。

## 本项目的检索与输出

按 coverage.json 核对业务内容，保留范围、条件、例外及完整清单。研究与提交协议以运行时工具为准；本文件只定义本专题的业务判断。

## 参考文件

运行时按阶段和当前工作提供规则；尚未提供的完整细则及示例可通过 read_file 按需查阅。

- `references/output_schema.json`：本项目机器格式声明，运行时从报告快照读取。
- `references/output_format.md`：事项组织、字段含义和实际 JSON 提交示例。
- `references/coverage.json`：本专题检索覆盖清单，未解决主题保留缺口。
- `references/extraction_rules.md`：专题检索与判断细则。
- `references/examples.md`：模拟原文块与逐条提交样例。
