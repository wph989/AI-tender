# 封装要求解析 Skill

## 适用场景
- 触发：项目控制器启动当前专题封装要求解析任务时调用。
- 输入：授权资料清单与按需检索得到的原文块，不预先灌入全文。
- 输出：完成检索后按专题模板综合的 content JSON，逐条附独立的原文溯源引用。

## 领域知识

封装要求是招标文件中对投标文件制作和提交形式的规定，主要包括：

1. **份数要求**：正本/副本各需几份
2. **密封要求**：密封方式、密封袋要求
3. **标记要求**：封面标注内容（项目名称、编号、投标人等）
4. **分册要求**：技术标/商务标/价格标是否分开封装
5. **电子版要求**：U盘/光盘、文件格式
6. **装订要求**：胶装/活页、页码编排
7. **组成与签章**：文件组成、签字人资格、盖章位置和类型

本模块提取具体制作与提交要求，不提取投标文件格式大纲的章节树结构，也不把技术、商务或资格内容本身当作格式要求。

## 识别规则

关键词种子（可扩展，不限于）："封装"、"密封"、"装订"、"正本"、"副本"、"份数"、"标记"、"包装"

## 执行流程

1. **主题检索**：使用 `search_document` 搜索"封装""密封""装订"等章节
2. **扩展上下文**：根据命中位置使用 `read_document` 读取相邻条款
3. **提取要求**：提取组成、格式、签章、密封、份数、纸质版和电子版要求
4. **输出结果**：按本 Skill 的输出协议调用 submit_analysis；没有依据的条目省略。

## 本项目的检索与输出

- 输入是授权资料清单及检索返回的 id/text 原文块。先核对主文件、澄清、补遗和相关附件，按 coverage.json 的业务主题继续检索；关键词只是线索，不保证完整召回。
- list_documents 返回资料ID与说明；search_document 检索本项目，search_knowledge 检索关联参考库。参考资料不能替代项目依据，参考建议也需要引用本项目相关要求。
- 遇到转引按目标名称、章节或业务主题继续检索，read_document 围绕已读 block_id 补读表头、脚注和条件；不猜测ID、磁盘路径或全文行号。未命中、缺失目标及预算不足如实登记。
- 按 coverage.json 的 checks 逐项核对。某个子主题已有可靠事项即提交，topic_updates 同步登记核对项、适用范围、证据和具体待办；新增证据仅复核相关事项。全部主题处理后由运行时独立查漏。未命中不等于文件未约定。
- 按 output_format.md 批量调用 submit_analysis，每次最多三条完整事项；相互独立的事项可放在同一批，有父子或端点依赖的事项分步提交。content 承载业务内容，citations 独立提供已读ID及连续原文；不同标段或条件不强行合并。
- 内容处理充分后运行时自动独立查漏，无须额外空提交；final=true 只请求检查完成条件，未决主题及待办须明确记录。遇到工具错误按实际反馈和剩余额度纠正，不自行设定重试次数。
- 权限、调用预算、结构和支持性校验由运行时执行。read_file 只读取当前 Skill 的参考文件或会话历史；不读取招标文件磁盘路径，不递归委派子Agent。

## 参考文件

运行时首次推理前已加载正文、输出说明、核心细则和明确品类的规则；无需重复读取，示例按需通过 read_file 查阅。

- `references/output_schema.json`：本项目机器格式声明，运行时从报告快照读取。
- `references/output_format.md`：事项组织、字段含义和实际 JSON 提交示例。
- `references/coverage.json`：本专题检索覆盖清单，未解决主题保留缺口。
- `references/extraction_rules.md`：专题检索与判断细则。
- `references/examples.md`：模拟原文块与逐条提交样例。
