# 企业业绩解析 Skill

## 适用场景
- 触发：项目控制器启动当前专题企业业绩解析任务时调用。
- 输入：授权资料清单与按需检索得到的原文块，不预先灌入全文。
- 输出：submit_analysis 原生工具提交的字段（field/group/sort_order/values/note），每个值附已读取原文块的引用。

## 领域知识

企业业绩要求是招标文件中对投标人历史项目经验和能力的规定，主要包括：

1. **类似项目定义**：什么是"类似项目"（行业、规模、金额等界定标准）
2. **业绩数量要求**：需提供几个类似项目业绩
3. **时间范围**：业绩的时间窗口（如近3年、近5年）
4. **金额要求**：单个项目的最低合同金额
5. **证明材料**：需提供什么证明（合同、中标通知书、验收报告等）
6. **认定标准**：已完工/在建/已签约的不同认定规则

要求的主语必须是投标人企业的过往项目经验。企业资质、人员个人业绩、财务状况、设备设施、信誉、技术方案及其他资格条件必须排除。

## 识别规则

关键词种子（可扩展，不限于）："业绩"、"类似项目"、"同类项目"、"合同"、"中标通知书"、"验收"

## 执行流程

1. **精确检索**：使用 `search_document` 搜索"业绩""类似项目"等章节
2. **扩展上下文**：根据命中位置使用 `read_document` 读取相邻条款
3. **主语判断**：确认要求针对企业历史项目，而非人员或企业资质
4. **完整提取**：保留业绩类型、数量、时间、金额、认定口径、证明材料及评分规则
5. **输出结果**：按本 Skill 的输出协议调用 submit_analysis；没有依据的条目省略。

## 输出协议

通过原生工具调用 `submit_analysis(fields, relations, research_summary)` 提交结果。
每个字段包含 field、group、sort_order、values、note；values 中每个值包含 value 与 citations，证据逐值绑定。
引用使用 {"block_id":"工具实际返回的块ID","quote":"块内连续原文"}；不能引用 Skill、压缩摘要或常识。
同一字段出现多个值时每个值各自成条并带自己的引用，不合并成一段文字；一个值可有多条引用。
没有相关依据可提交空 fields，但 research_summary 必须说明检索过的主题、缺口与不确定性。
补充文件明确修改条款时保留修改前后双方引用；参考库内容只作建议，不能替代本项目要求。

## 参考文件（按标类型加载）
根据任务 category 及 lots 中的类别覆盖，加载对应子目录下的参考文件：
- `references/output_format.md`：本 Skill 专属输出模板和格式约束
- `references/<type_dir>/extraction_rules.md`：“类似项目”定义提取、时间窗口、证明材料、强制/加分区分、严禁行为、自检清单
- `references/<type_dir>/examples.md`：完整业绩要求提取样例
- category 取值：service（服务类）、engineering（工程类）、goods（货物类）；type_dir 使用相同值
- 类别由用户选择并由运行时提供；不能自行默认成服务类，标段有覆盖类别时同时参考对应规则

## 工具与证据

- 运行时先调用 `load_skill` 加载本文件及 `references/output_format.md`，无需重复读取；其余细则按需读取。
- `list_documents()`：返回授权资料的 id 和说明文本；资料 id 可填入检索的 source_id。
- `search_document(query, source_id?)`：检索本项目；`search_knowledge(query, source_id?)`：检索关联参考库。
- 检索证据只含 `id`、`text`。把证据 id 填入引用的 `block_id`；quote 必须是该 text 的连续原文。
- `read_document(block_id, before=2, after=2)`：围绕已读证据补读；before/after 合计最多11，均为0时只补读本块。不得猜测ID或扫描全文。
- `read_file(file_path)`：只读 `/skills/company-performance-parsing/references/` 下当前任务需要的细则，或压缩历史；不能读取招标文件磁盘路径。
- `submit_analysis`：结构化提交，普通字段每批最多3条，大纲每批最多6节点；`final=false` 暂存，明确核对完成后 `final=true`。

## 证据选择与纠错

1. 先按本专题的问题检索，再核对主体、标段、表头、脚注、条件和补充文件。上下文不足时按证据ID补读；不能用关键词命中代替事实判断。
2. 同一事实在相同适用范围内重复出现，选最直接、完整的一处。跨块条件、不同标段、修订前后和未决冲突所需的证据分别保留；检索相似度和自报置信分数不作为可信度。
3. 引用只提交ID和连续摘录，不生成页码、坐标、文件路径或来源元数据。服务端校验实际读取记录、资料权限和版本后，按保留的ID补齐定位。
4. 工具返回结构化错误时，按 `message` 和 `remaining_attempts` 修正；只补交未通过部分，不重交已保存事实。更换字段名或重复相同请求不会获得新额度。
5. 收到收尾提示就停止扩展检索，提交已有可靠结果并在 `research_summary` 记录缺口；不得声称缺口是文件未约定。不得再委派子Agent，服务故障与重试由运行时处理。

## 注意
- "类似项目"的定义是关键，必须精确提取
- 注意区分"必须提供"和"提供加分"
- 注意证明材料的具体要求（合同关键页还是全文）
- 业绩评分只提取评分对象明确为企业业绩的规则
